# 测试环境地址配置指南

## 问题诊断

当前错误：`getaddrinfo ENOTFOUND test.yaohufox.com`

这说明 `test.yaohufox.com` 域名不存在或无法解析。

## 解决方案

根据您的实际部署情况，选择以下配置之一：

### 方案1：测试环境使用生产域名 + 端口（最可能）

如果测试环境和生产环境在同一服务器上，使用相同域名但不同端口：

**配置**：
```
https://yaohufox.com:8082
```
或
```
http://yaohufox.com:8082
```

**在 Postman 中设置**：
1. 点击右上角环境选择器 → "测试环境" → "Edit"
2. 将 `base_url` 的 Current Value 改为：`https://yaohufox.com:8082`
3. 保存

### 方案2：测试环境使用服务器IP + 端口

如果测试环境使用服务器IP地址：

**配置**：
```
http://服务器IP:8082
```

**示例**：
```
http://123.456.789.0:8082
```

**在 Postman 中设置**：
1. 将 `base_url` 改为：`http://您的服务器IP:8082`
2. 保存

### 方案3：测试环境使用本地地址（如果服务在本地）

如果测试环境服务运行在本地：

**配置**：
```
http://localhost:8082
```

**前提条件**：
- 服务必须在本地运行
- 端口8082必须被占用

### 方案4：测试环境使用生产环境（临时方案）

如果测试环境暂时不可用，可以先用生产环境测试：

**配置**：
```
https://yaohufox.com
```

**注意**：这会直接操作生产数据，请谨慎使用。

## 快速测试方法

### 方法1：使用浏览器测试

在浏览器中直接访问以下URL，看哪个能正常访问：

1. `https://yaohufox.com:8082/api/test/hello`
2. `http://yaohufox.com:8082/api/test/hello`
3. `http://您的服务器IP:8082/api/test/hello`
4. `http://localhost:8082/api/test/hello`

能正常访问的地址就是正确的测试环境地址。

### 方法2：使用 curl 测试

```bash
# 测试方案1：HTTPS + 端口
curl https://yaohufox.com:8082/api/test/hello

# 测试方案2：HTTP + 端口
curl http://yaohufox.com:8082/api/test/hello

# 测试方案3：服务器IP（替换为实际IP）
curl http://123.456.789.0:8082/api/test/hello

# 测试方案4：本地
curl http://localhost:8082/api/test/hello
```

### 方法3：检查服务器端口

在服务器上执行：

```bash
# 检查8082端口是否被占用
netstat -tln | grep 8082
# 或
ss -tln | grep 8082

# 查看应用日志
tail -f /opt/yaohufox/testing/app.log
```

## 推荐配置（根据实际情况选择）

### 如果测试环境在生产服务器上（端口8082）

```json
{
  "key": "base_url",
  "value": "https://yaohufox.com:8082"
}
```

### 如果测试环境有独立服务器

```json
{
  "key": "base_url",
  "value": "http://测试服务器IP:8082"
}
```

### 如果测试环境在本地

```json
{
  "key": "base_url",
  "value": "http://localhost:8082"
}
```

## 在 Postman 中修改步骤

1. **打开环境设置**
   - 点击右上角环境选择器
   - 点击 "测试环境" 右侧的 "..." → "Edit"

2. **修改 base_url**
   - 找到 `base_url` 变量
   - 修改 "Current Value" 为正确的地址
   - 点击 "Save"

3. **验证**
   - 确认已选择 "测试环境"
   - 打开 "健康检查" 接口
   - 点击 "Send"
   - 应该返回 `Hello World!`

## 常见问题

### Q: 如何知道测试环境的实际地址？

A: 可以通过以下方式确认：
1. 查看 Jenkins 部署日志
2. 查看服务器上的应用配置
3. 询问运维人员
4. 使用浏览器/curl 逐个测试可能的地址

### Q: 使用 IP 地址还是域名？

A: 
- **域名**：更规范，但需要配置DNS
- **IP地址**：直接可用，但IP可能变化

### Q: HTTPS 还是 HTTP？

A:
- **HTTPS**：更安全，但需要配置SSL证书
- **HTTP**：简单，但不够安全

如果 `https://yaohufox.com:8082` 不行，试试 `http://yaohufox.com:8082`

### Q: 端口号是什么？

A: 根据 Jenkinsfile 配置：
- 生产环境：8081（通过Nginx代理，外部访问是443/80）
- 测试环境：8082

## 下一步操作

1. **确定测试环境地址**
   - 使用浏览器测试可能的地址
   - 或查看服务器配置

2. **更新 Postman 配置**
   - 在 Postman 中修改 `base_url`

3. **测试连接**
   - 运行 "健康检查" 接口
   - 确认能正常返回

4. **如果仍然失败**
   - 检查防火墙设置
   - 检查服务是否正常运行
   - 查看服务端日志

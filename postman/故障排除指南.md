# Postman 连接失败故障排除指南

## 问题现象

Postman 调用接口时出现错误：
```
Error: connect ECONNREFUSED 127.0.0.1:8082
```

## 原因分析

这个错误表示 Postman 尝试连接 `127.0.0.1:8082`（本地8082端口）失败，可能的原因：

1. **测试环境部署在服务器上，不在本地**
   - 当前配置使用 `http://localhost:8082`
   - 但服务实际部署在服务器上

2. **本地服务未运行**
   - 如果测试环境确实在本地，但服务没有启动

3. **端口配置错误**
   - 服务运行在不同的端口

## 解决方案

### 方案1：测试环境在服务器上（推荐）

如果测试环境部署在服务器上，需要更新测试环境配置：

#### 步骤1：确定测试环境地址

测试环境的地址可能是：
- `https://test.yaohufox.com` （如果有测试域名）
- `http://服务器IP:8082` （如果使用IP访问）
- `https://yaohufox.com:8082` （如果使用同一域名不同端口）

#### 步骤2：更新 Postman 环境配置

1. 在 Postman 中点击右上角的环境选择器
2. 点击 **"测试环境"** 右侧的 **"..."** 或 **"Edit"**
3. 找到 `base_url` 变量
4. 将值从 `http://localhost:8082` 改为实际的服务器地址
5. 点击 **"Save"** 保存

#### 步骤3：重新测试

1. 确认已选择 **"测试环境"**
2. 打开 **"健康检查"** 接口
3. 点击 **"Send"**
4. 应该能正常连接

### 方案2：测试环境在本地

如果测试环境确实在本地运行，需要：

#### 步骤1：检查服务是否运行

```bash
# 检查端口是否被占用
netstat -an | grep 8082
# 或
lsof -i :8082
```

#### 步骤2：检查服务日志

```bash
# 查看应用日志
tail -f /opt/yaohufox/testing/app.log
```

#### 步骤3：手动启动服务（如果需要）

```bash
cd /opt/yaohufox/testing
java -jar -Dspring.profiles.active=testing -Dserver.port=8082 app.jar
```

### 方案3：使用生产环境测试

如果测试环境暂时不可用，可以先使用生产环境：

1. 在 Postman 右上角选择 **"生产环境"**
2. 测试接口应该能正常连接（`https://yaohufox.com`）

## 快速检查清单

- [ ] 确认已选择正确的环境（右上角环境选择器）
- [ ] 检查 `base_url` 变量值是否正确
- [ ] 如果使用服务器地址，确认网络连接正常
- [ ] 如果使用本地地址，确认服务正在运行
- [ ] 检查防火墙设置（如果使用服务器IP）
- [ ] 尝试使用浏览器直接访问接口URL

## 验证连接

### 方法1：使用 curl 测试

```bash
# 测试生产环境
curl https://yaohufox.com/api/test/hello

# 测试本地8082端口（如果服务在本地）
curl http://localhost:8082/api/test/hello

# 测试服务器IP（替换为实际IP）
curl http://服务器IP:8082/api/test/hello
```

### 方法2：在浏览器中测试

直接在浏览器中访问：
- 生产环境：`https://yaohufox.com/api/test/hello`
- 测试环境：`http://服务器地址:8082/api/test/hello`

如果浏览器能正常访问，说明服务正常，问题在 Postman 配置。

## 常见错误及解决方法

### 错误1：ECONNREFUSED
**原因**：无法连接到服务器
**解决**：检查服务器地址、端口、防火墙设置

### 错误2：SSL/TLS 错误
**原因**：HTTPS 证书问题
**解决**：在 Postman Settings → General 中关闭 SSL 验证（仅测试环境）

### 错误3：404 Not Found
**原因**：URL路径错误
**解决**：检查 `base_url` 和接口路径是否正确

### 错误4：Timeout
**原因**：请求超时
**解决**：增加超时时间（Settings → General → Request timeout）

# 应用未启动诊断指南

## 问题症状

- `curl http://localhost:8081/actuator/health` 返回 `Connection refused`
- `curl https://yaohufox.com/api/test/hello` 返回 `502 Bad Gateway`
- 说明应用进程没有运行或没有监听端口

## 快速诊断步骤

### 1. 检查应用进程

```bash
# 检查是否有 Java 进程运行
ps aux | grep java | grep app.jar

# 检查 PID 文件
if [ -f /opt/yaohufox/production/app.pid ]; then
    PID=$(cat /opt/yaohufox/production/app.pid)
    echo "PID 文件中的进程 ID: $PID"
    ps -p $PID
else
    echo "❌ PID 文件不存在"
fi
```

### 2. 检查端口监听

```bash
# 检查端口 8081 是否被监听
netstat -tln | grep ":8081 " || ss -tln | grep ":8081 "

# 或者使用 lsof
sudo lsof -i :8081
```

### 3. 查看应用日志（最重要）

```bash
# 查看最新日志
tail -100 /opt/yaohufox/production/app.log

# 查看错误信息
tail -200 /opt/yaohufox/production/app.log | grep -i "error\|exception\|failed"
```

### 4. 检查应用文件

```bash
# 检查 JAR 文件是否存在
ls -lh /opt/yaohufox/production/app.jar

# 检查目录权限
ls -la /opt/yaohufox/production/
```

## 常见原因及解决方案

### 原因 1: 应用启动失败

**症状**: PID 文件不存在或进程立即退出

**解决方案**:
```bash
# 查看启动日志找出失败原因
tail -200 /opt/yaohufox/production/app.log

# 根据错误信息修复问题后，手动启动测试
cd /opt/yaohufox/production
source .env 2>/dev/null || . .env

nohup java -jar \
  -Dspring.profiles.active=production \
  -Dserver.port=8081 \
  -Dspring.datasource.url="${SPRING_DATASOURCE_URL}" \
  -Dspring.datasource.username="${SPRING_DATASOURCE_USERNAME}" \
  -Dspring.datasource.password="${SPRING_DATASOURCE_PASSWORD}" \
  app.jar > app.log 2>&1 &

echo $! > app.pid
echo "应用已启动，PID: $(cat app.pid)"

# 等待几秒后检查
sleep 5
curl http://localhost:8081/api/test/hello
```

### 原因 2: Jenkins 部署失败

**症状**: 最新的 Jenkins 构建失败

**解决方案**:
1. 查看 Jenkins 构建日志
2. 检查是否有语法错误或配置问题
3. 修复后重新构建

### 原因 3: 数据库连接失败

**症状**: 日志中显示数据库连接错误

**解决方案**:
```bash
# 检查数据库是否运行
sudo systemctl status postgresql

# 测试数据库连接
psql -U yaohu -d mahjong_scoreboard_system -h localhost -c "SELECT 1;"

# 如果连接失败，检查密码
# 重置密码（如果需要）
sudo -u postgres psql -c "ALTER USER yaohu WITH PASSWORD 'cch815566';"
```

### 原因 4: 端口被占用

**症状**: 端口 8081 被其他进程占用

**解决方案**:
```bash
# 查找占用端口的进程
sudo lsof -i :8081

# 如果不需要该进程，停止它
sudo kill -9 <PID>
```

## 完整诊断脚本

将以下脚本保存为 `diagnose-app.sh` 并执行：

```bash
#!/bin/bash

echo "=========================================="
echo "应用未启动诊断"
echo "=========================================="
echo ""

# 1. 检查进程
echo "1. 检查应用进程..."
if [ -f /opt/yaohufox/production/app.pid ]; then
    PID=$(cat /opt/yaohufox/production/app.pid)
    if ps -p $PID > /dev/null 2>&1; then
        echo "   ✅ 进程运行中 (PID: $PID)"
        ps -p $PID -o pid,cmd
    else
        echo "   ❌ 进程不存在 (PID: $PID)"
    fi
else
    echo "   ❌ PID 文件不存在"
fi

echo ""

# 2. 检查端口
echo "2. 检查端口监听..."
if netstat -tln 2>/dev/null | grep -q ":8081 " || ss -tln 2>/dev/null | grep -q ":8081 "; then
    echo "   ✅ 端口 8081 正在监听"
    netstat -tln | grep ":8081 " || ss -tln | grep ":8081 "
else
    echo "   ❌ 端口 8081 未监听"
fi

echo ""

# 3. 检查文件
echo "3. 检查应用文件..."
if [ -f /opt/yaohufox/production/app.jar ]; then
    echo "   ✅ app.jar 存在 ($(ls -lh /opt/yaohufox/production/app.jar | awk '{print $5}'))"
else
    echo "   ❌ app.jar 不存在"
fi

if [ -f /opt/yaohufox/production/.env ]; then
    echo "   ✅ .env 文件存在"
else
    echo "   ❌ .env 文件不存在"
fi

echo ""

# 4. 查看日志
echo "4. 查看最新日志（最后 20 行）..."
if [ -f /opt/yaohufox/production/app.log ]; then
    tail -20 /opt/yaohufox/production/app.log
else
    echo "   ❌ 日志文件不存在"
fi

echo ""

# 5. 检查错误
echo "5. 查找错误信息..."
if [ -f /opt/yaohufox/production/app.log ]; then
    ERRORS=$(tail -100 /opt/yaohufox/production/app.log | grep -i "error\|exception\|failed" | tail -5)
    if [ -n "$ERRORS" ]; then
        echo "   最近的错误："
        echo "$ERRORS"
    else
        echo "   ✅ 未发现明显错误"
    fi
else
    echo "   ⚠️  日志文件不存在，无法检查错误"
fi

echo ""
echo "=========================================="
```

## 手动启动应用

如果诊断后需要手动启动应用：

```bash
cd /opt/yaohufox/production

# 1. 加载环境变量
if [ -f .env ]; then
    set -a
    . .env
    set +a
    echo "✅ 环境变量已加载"
else
    echo "⚠️  .env 文件不存在，使用默认值"
    export SPRING_DATASOURCE_URL="jdbc:postgresql://localhost:5432/mahjong_scoreboard_system"
    export SPRING_DATASOURCE_USERNAME="yaohu"
    export SPRING_DATASOURCE_PASSWORD="cch815566"
fi

# 2. 确保端口和数据库配置正确
export SERVER_PORT=8081
export SPRING_DATASOURCE_URL=${SPRING_DATASOURCE_URL:-jdbc:postgresql://localhost:5432/mahjong_scoreboard_system}
export SPRING_DATASOURCE_USERNAME=${SPRING_DATASOURCE_USERNAME:-yaohu}
export SPRING_DATASOURCE_PASSWORD=${SPRING_DATASOURCE_PASSWORD:-cch815566}

# 3. 启动应用
echo "启动应用..."
nohup java -jar \
  -Dspring.profiles.active=production \
  -Dserver.port=8081 \
  -Dspring.datasource.url="${SPRING_DATASOURCE_URL}" \
  -Dspring.datasource.username="${SPRING_DATASOURCE_USERNAME}" \
  -Dspring.datasource.password="${SPRING_DATASOURCE_PASSWORD}" \
  app.jar > app.log 2>&1 &

# 4. 保存 PID
echo $! > app.pid
echo "应用已启动，PID: $(cat app.pid)"

# 5. 等待启动
echo "等待应用启动..."
sleep 10

# 6. 验证
echo "验证应用状态..."
if curl -f -s http://localhost:8081/api/test/hello > /dev/null 2>&1; then
    echo "✅ 应用启动成功"
    curl http://localhost:8081/api/test/hello
else
    echo "❌ 应用启动失败，查看日志："
    tail -50 app.log
fi
```

## 验证修复

启动后，使用以下命令验证：

```bash
# 1. 检查进程
ps -p $(cat /opt/yaohufox/production/app.pid)

# 2. 检查端口
netstat -tln | grep ":8081 "

# 3. 测试接口
curl http://localhost:8081/api/test/hello

# 4. 健康检查
curl http://localhost:8081/actuator/health

# 5. 通过域名访问（如果 Nginx 配置正确）
curl https://yaohufox.com/api/test/hello
```

## 总结

应用未启动的常见原因：
1. **应用启动失败** - 查看日志找出原因
2. **数据库连接失败** - 检查数据库和密码
3. **端口被占用** - 检查并释放端口
4. **文件权限问题** - 检查文件和目录权限
5. **环境变量未设置** - 检查 .env 文件

按照上述步骤逐一排查，通常能找到问题所在。

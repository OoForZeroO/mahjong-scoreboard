# 阿里云服务器环境搭建指南

## 一、服务器目录结构设计

### 1.1 创建基础目录结构

在服务器上执行以下命令创建目录：

```bash
# 进入项目目录
cd /opt

# 创建主目录结构
sudo mkdir -p yaohufox/{config,certificates,data,logs,scripts}

# 创建配置目录
sudo mkdir -p yaohufox/config/{nginx,jenkins}
sudo mkdir -p yaohufox/config/nginx/{sites-available,sites-enabled}

# 创建证书目录
sudo mkdir -p yaohufox/certificates/{prod,test,jenkins}

# 创建数据目录
sudo mkdir -p yaohufox/data/{postgres-prod,postgres-test,jenkins}

# 创建日志目录
sudo mkdir -p yaohufox/logs/{nginx,postgres,app}

# 创建应用目录（生产环境和测试环境）
sudo mkdir -p yaohufox/{production,testing}

# 设置权限（使用你的用户名替换 your_username）
sudo chown -R your_username:your_username /opt/yaohufox
```

**目录说明：**
- `config/` - 配置文件（Nginx、Jenkins 分离，避免污染）
- `certificates/` - SSL 证书（生产、测试、Jenkins 分离）
- `data/` - 持久化数据（数据库、Jenkins 数据）
- `logs/` - 日志文件（按服务分类）
- `scripts/` - 运维脚本
- `production/` - 生产环境应用
- `testing/` - 测试环境应用

## 二、Docker 环境准备

### 2.1 安装 Docker 和 Docker Compose

```bash
# 更新系统
sudo yum update -y

# 安装 Docker
sudo yum install -y docker

# 启动 Docker 服务
sudo systemctl start docker
sudo systemctl enable docker

# 安装 Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# 验证安装
docker --version
docker-compose --version
```

### 2.2 配置 Docker 用户组（避免每次使用 sudo）

```bash
# 将当前用户添加到 docker 组
sudo usermod -aG docker $USER

# 重新登录或执行以下命令使组生效
newgrp docker

# 验证（应该不需要 sudo）
docker ps
```

## 三、PostgreSQL 数据库配置

### 3.1 创建生产环境数据库配置

创建文件：`/opt/yaohufox/production/docker-compose.yml`

**注意：** 新版本的 Docker Compose 不再需要 `version` 字段，直接省略即可。

```yaml
services:
  postgresql-prod:
    image: postgres:15-alpine
    container_name: yaohufox-postgres-prod
    restart: always
    environment:
      POSTGRES_DB: mahjong_score_system
      POSTGRES_USER: mahjong_user
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}  # 从环境变量读取
      PGDATA: /var/lib/postgresql/data/pgdata
    ports:
      - "127.0.0.1:5432:5432"  # 只允许本地连接
    volumes:
      - /opt/yaohufox/data/postgres-prod:/var/lib/postgresql/data
      - /opt/yaohufox/config/postgres-init-prod.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - yaohufox-network-prod
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U mahjong_user -d mahjong_score_system"]
      interval: 10s
      timeout: 5s
      retries: 5
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"

  mahjong-app-prod:
    image: mahjong-scoreboard:latest  # Jenkins 构建的镜像
    container_name: yaohufox-app-prod
    restart: always
    ports:
      - "127.0.0.1:8081:8080"  # 映射到 8081，只允许本地访问
    environment:
      - SPRING_PROFILES_ACTIVE=production
      - SPRING_DATASOURCE_URL=jdbc:postgresql://postgresql-prod:5432/mahjong_score_system
      - SPRING_DATASOURCE_USERNAME=mahjong_user
      - SPRING_DATASOURCE_PASSWORD=${POSTGRES_PASSWORD}
      - SERVER_PORT=8080
      - WECHAT_APPID=${WECHAT_APPID}
      - WECHAT_APPSECRET=${WECHAT_APPSECRET}
    volumes:
      - /opt/yaohufox/logs/app/production:/app/logs
    depends_on:
      postgresql-prod:
        condition: service_healthy
    networks:
      - yaohufox-network-prod
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"

networks:
  yaohufox-network-prod:
    driver: bridge
```

### 3.5 启动数据库和应用

**重要提示：** 首次部署时，应用镜像 `mahjong-scoreboard:latest` 还不存在（需要通过 Jenkins 构建），所以建议分步启动：

**第一步：只启动数据库（生产环境）**
```bash
cd /opt/yaohufox/production
docker-compose --env-file .env up -d postgresql-prod
```

**第二步：只启动数据库（测试环境）**
```bash
cd /opt/yaohufox/testing
```

**第三步：等待 Jenkins 构建应用镜像**
- 在 Jenkins 中触发构建任务
- 等待构建完成

**第四步：启动应用服务**
```bash
# 生产环境
cd /opt/yaohufox/production
docker-compose --env-file .env up -d

# 测试环境
cd /opt/yaohufox/testing
docker-compose --env-file .env up -d
```

**如果应用镜像已存在，可以直接启动所有服务：**

```bash
docker-compose --env-file .env up -d
```

## 四、Nginx 反向代理配置

### 4.1 安装 Nginx

```bash
sudo yum install -y nginx

# 启动 Nginx
sudo systemctl start nginx
sudo systemctl enable nginx
```

### 4.2 配置生产环境反向代理

**创建配置文件：**

```bash
sudo vi /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf
```

将以下内容写入文件：

```nginx
# 生产环境配置 - yaohufox.com
upstream mahjong_production {
    server 127.0.0.1:8081;  # Spring Boot 应用端口
}

server {
    listen 80;
    server_name yaohufox.com www.yaohufox.com;
    
    # 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yaohufox.com www.yaohufox.com;

    # SSL 证书配置
    ssl_certificate /opt/yaohufox/certificates/prod/fullchain.pem;
    ssl_certificate_key /opt/yaohufox/certificates/prod/privkey.pem;
    
    # SSL 优化配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 日志
    access_log /opt/yaohufox/logs/nginx/production-access.log;
    error_log /opt/yaohufox/logs/nginx/production-error.log;

    # 客户端上传大小限制
    client_max_body_size 10M;

    # API 代理
    location / {
        proxy_pass http://mahjong_production;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket 支持（如果需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 健康检查端点
    location /health {
        proxy_pass http://mahjong_production/actuator/health;
        access_log off;
    }
}
```

### 4.4 启用 Nginx 配置

**首先验证配置文件是否存在：**

```bash
# 检查配置文件是否已创建
ls -la /opt/yaohufox/config/nginx/sites-available/

# 应该看到：
# mahjong-production.conf
# mahjong-testing.conf
```

**创建符号链接启用配置：**

```bash
# 确保 sites-enabled 目录存在
sudo mkdir -p /opt/yaohufox/config/nginx/sites-enabled

# 创建符号链接启用配置
sudo ln -s /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf /opt/yaohufox/config/nginx/sites-enabled/
sudo ln -s /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf /opt/yaohufox/config/nginx/sites-enabled/

# 验证符号链接是否创建成功
ls -la /opt/yaohufox/config/nginx/sites-enabled/

# 应该看到指向配置文件的符号链接
```

**在 Nginx 主配置文件中包含 sites-enabled：**

```bash
sudo vi /etc/nginx/nginx.conf
```

在 `http {` 块中添加：
```nginx
include /opt/yaohufox/config/nginx/sites-enabled/*.conf;
```

**验证主配置文件：**

```bash
# 检查 include 语句是否正确添加
grep -n "sites-enabled" /etc/nginx/nginx.conf

# 应该看到类似这样的输出：
# 32:    include /opt/yaohufox/config/nginx/sites-enabled/*.conf;
```

### 4.4.1 故障排除：Nginx 配置验证失败

**如果执行 `sudo nginx -t` 时出现 "No such file or directory" 错误，请按以下步骤诊断和修复：**

**步骤 1：完整诊断脚本**

```bash
#!/bin/bash
echo "=== Nginx 配置诊断 ==="
echo ""

echo "1. 检查目录结构："
echo "   /opt/yaohufox/config/nginx/sites-available/"
ls -la /opt/yaohufox/config/nginx/sites-available/ 2>/dev/null || echo "   ❌ 目录不存在或为空"
echo ""

echo "2. 检查符号链接："
echo "   /opt/yaohufox/config/nginx/sites-enabled/"
ls -la /opt/yaohufox/config/nginx/sites-enabled/ 2>/dev/null || echo "   ❌ 目录不存在或为空"
echo ""

echo "3. 检查主配置文件："
grep -n "sites-enabled" /etc/nginx/nginx.conf 2>/dev/null || echo "   ❌ include 语句未找到"
echo ""

echo "4. 检查配置文件内容："
if [ -f /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf ]; then
    echo "   ✅ mahjong-production.conf 存在"
    head -5 /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf
else
    echo "   ❌ mahjong-production.conf 不存在"
fi
echo ""

if [ -f /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf ]; then
    echo "   ✅ mahjong-testing.conf 存在"
    head -5 /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf
else
    echo "   ❌ mahjong-testing.conf 不存在"
fi
```

### 4.6 配置 Jenkins 反向代理

**重要：** Jenkins 需要单独的 Nginx 配置和 SSL 证书。

**步骤 1：创建 Jenkins Nginx 配置文件**

```bash
sudo vi /opt/yaohufox/config/nginx/sites-available/jenkins.conf
```

将以下内容写入文件：

```nginx
# Jenkins 配置 - jenkins.yaohufox.com
upstream jenkins_backend {
    server 127.0.0.1:8080;  # Jenkins 默认端口（根据实际 Jenkins 端口调整）
}

server {
    listen 80;
    server_name jenkins.yaohufox.com;
    
    # 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name jenkins.yaohufox.com;

    # SSL 证书配置
    ssl_certificate /opt/yaohufox/certificates/jenkins/fullchain.pem;
    ssl_certificate_key /opt/yaohufox/certificates/jenkins/privkey.pem;
    
    # SSL 优化配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 日志
    access_log /opt/yaohufox/logs/nginx/jenkins-access.log;
    error_log /opt/yaohufox/logs/nginx/jenkins-error.log;

    # Jenkins 需要较大的上传限制（用于上传构建产物）
    client_max_body_size 100M;

    # Jenkins 代理配置
    location / {
        proxy_pass http://jenkins_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket 支持（Jenkins 需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # 超时设置（Jenkins 构建可能需要较长时间）
        proxy_connect_timeout 300s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;
        
        # Jenkins 特定配置
        proxy_redirect http:// https://;
    }
}
```

### 4.6.1 Jenkins SSL 证书故障排除

**错误：`NET::ERR_CERT_COMMON_NAME_INVALID`**

这个错误表示 SSL 证书的域名与访问的域名不匹配。解决方法：

**方法 1：检查证书域名**

```bash
# 查看证书的域名信息
openssl x509 -in /opt/yaohufox/certificates/jenkins/fullchain.pem -text -noout | grep -A 2 "Subject Alternative Name"

# 或者查看证书的 Subject
openssl x509 -in /opt/yaohufox/certificates/jenkins/fullchain.pem -text -noout | grep "Subject:"
```

**方法 2：临时使用自签名证书（仅用于测试）**

```bash
# 生成自签名证书（仅用于测试，浏览器会显示警告）
sudo mkdir -p /opt/yaohufox/certificates/jenkins
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /opt/yaohufox/certificates/jenkins/privkey.pem \
  -out /opt/yaohufox/certificates/jenkins/fullchain.pem \
  -subj "/C=CN/ST=State/L=City/O=Organization/CN=jenkins.yaohufox.com"

sudo chmod 600 /opt/yaohufox/certificates/jenkins/privkey.pem
sudo chmod 644 /opt/yaohufox/certificates/jenkins/fullchain.pem

# 重启 Nginx
sudo systemctl reload nginx
```

**注意：** 自签名证书会导致浏览器显示安全警告，需要点击「高级」→「继续访问」才能进入。生产环境请使用正式证书。

**方法 3：检查 Nginx 配置是否正确加载**

## 五、端口配置说明

### 5.0 端口分配方案

为了避免端口冲突，系统使用以下端口分配：

| 服务 | 端口 | 说明 |
|------|------|------|
| **Jenkins** | 8080 | CI/CD 服务，已占用 |
| **生产环境应用** | 8081 | 生产环境 Spring Boot 应用端口 |
| **测试环境应用** | 8082 | 测试环境 Spring Boot 应用端口 |
| **PostgreSQL（生产）** | 5432 | 生产数据库端口 |
| **PostgreSQL（测试）** | 5433 | 测试数据库端口 |

**重要说明：**

1. **应用端口配置**
   - 生产环境端口在 `application-production.yml` 中配置：`server.port: 8081`
   - 测试环境端口在 `application-testing.yml` 中配置：`server.port: 8082`
   - 可以通过环境变量 `SERVER_PORT` 覆盖，例如：`export SERVER_PORT=8081`

2. **Nginx 反向代理配置**
   - 生产环境：Nginx 监听 443/80，反向代理到 `127.0.0.1:8081`
   - 测试环境：Nginx 监听 443/80，反向代理到 `127.0.0.1:8082`

3. **验证端口配置**
   ```bash
   # 检查端口占用
   netstat -tln | grep -E "8080|8081|8082"
   # 或
   ss -tln | grep -E "8080|8081|8082"
   
   # 检查应用端口
   curl http://localhost:8081/actuator/health  # 生产环境
   curl http://localhost:8082/actuator/health  # 测试环境
   ```

4. **修改端口（如果需要）**
   - 修改配置文件：`application-production.yml` 或 `application-testing.yml`
   - 更新 Nginx 配置中的 upstream 端口
   - 更新 Jenkinsfile 中的端口环境变量（`PRODUCTION_PORT` 或 `TESTING_PORT`）

     - 点击 **Save**（保存）后，Jenkins 会自动验证连接

   **重要：如何选择不同的 Jenkinsfile**

   - **使用 Docker 部署**：脚本路径填写 `Jenkinsfile`（默认）
   - **不使用 Docker 部署**：脚本路径填写 `Jenkinsfile.no-docker`

   **详细操作步骤：**

   1. 在 Pipeline 配置页面，找到「流水线」部分
   2. 找到「脚本路径」（Script Path）输入框
   3. 默认值是 `Jenkinsfile`
   4. 如果要使用非 Docker 部署，将脚本路径改为：`Jenkinsfile.no-docker`
   5. 点击 **Save**（保存）

   **如果仍然显示 "无法连接仓库" 错误：**

   根据不同的错误信息，按以下顺序检查：

   **错误类型 A：`Failed to setup credentials`（凭据设置失败）**

   这个错误表示 Jenkins 无法正确读取或使用你选择的凭据。

   **解决方法：**

   1. **检查凭据类型是否正确**
      - 进入 **Manage Jenkins** → **Manage Credentials**
      - 找到你使用的凭据（显示为 `OoForZeroO/******`）
      - 点击凭据查看详情
      - 确认 **Kind**（类型）是 `Username with password`，不是其他类型

   2. **重新创建凭据（推荐）**
      - 删除现有凭据（如果可能）
      - 按照步骤 3.2 重新创建凭据，确保：
        - **Kind**：选择 `Username with password`
        - **Username**：你的 GitHub 用户名（不是邮箱）
        - **Password**：粘贴完整的 Personal Access Token（以 `ghp_` 开头）
        - 不要有任何多余的空格或换行

   3. **验证 Token 是否有效**
      ```bash
      # 在服务器上测试 Token（替换 YOUR_USERNAME 和 YOUR_TOKEN）
      git ls-remote https://YOUR_USERNAME:YOUR_TOKEN@github.com/OoForZeroO/mahjong-scoreboard.git HEAD
      
      # 如果失败，说明 Token 无效或已过期
      ```

   4. **检查 Token 权限**
      - 登录 GitHub：https://github.com/settings/tokens
      - 找到你使用的 Token
      - 确认 Token 状态为 "Active"（活跃）
      - 确认 Token 有 `repo` scope（权限）

   5. **尝试使用 Secret text 类型的凭据**
      - 如果 `Username with password` 类型不工作，尝试：
        - **Kind**：选择 `Secret text`
        - **Secret**：粘贴完整的 Personal Access Token
        - **ID**：填写 `github-token`
        - **Description**：`GitHub Personal Access Token`
      - 然后在 Pipeline 配置中选择这个凭据

   6. **检查 Jenkins 凭据插件**
      - 进入 **Manage Jenkins** → **Manage Plugins** → **Installed**
      - 确认 **Credentials Plugin** 已安装
      - 如果没有，安装它并重启 Jenkins

   **错误类型 B：`git ls-remote` 失败（网络或 Git 配置问题）**

   1. **检查 Git 插件配置**
      - 确认 **Global Tool Configuration** 中 Git 路径正确
      - 确认 Git 插件已安装（**Manage Plugins** → **Installed** → 搜索 "Git plugin"）

   2. **检查网络连接**
      - 在服务器上测试：`git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD`
      - 以 Jenkins 系统用户测试：`sudo -u jenkins git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD`

   3. **检查凭据配置**
      - 确认凭据已正确选择（不要选择 "- 无 -"）
      - 检查 Personal Access Token 是否有效（未过期）
      - 检查 Token 是否有 `repo` 权限

   4. **查看 Jenkins 日志**
      - **Manage Jenkins** → **System Log** → **All Jenkins Logs**
      - 或查看服务器日志：`sudo tail -f /var/log/jenkins/jenkins.log`
      - 查找与 Git 或凭据相关的错误信息

5. **保存并构建**

   - 点击「保存」
   - 点击「立即构建」测试

   ```bash
   # 在服务器上测试（不需要认证）
   ```

4. **验证凭据是否有效**

   ```bash
   # 在 Jenkins 服务器上测试（替换 YOUR_USERNAME 和 YOUR_TOKEN）
   git ls-remote https://YOUR_USERNAME:YOUR_TOKEN@github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   ```

6. **服务器上 git ls-remote 正常，但 Jenkins 无法连接（特殊问题）**

   **重要说明：** 这里的"Jenkins 用户"指的是**运行 Jenkins 服务的系统用户**（Linux 用户，通常是 `jenkins`），**不是**登录 Jenkins Web 界面的用户名。Jenkins 服务在服务器上以某个系统用户身份运行，这个用户需要有执行 Git 命令的权限。

   这是最常见的问题，通常是因为 Jenkins 运行的系统用户无法访问 Git 或网络配置不同。

   **解决方法 A：检查 Jenkins 运行的系统用户**

   ```bash
   # 1. 查看 Jenkins 服务运行的系统用户
   ps aux | grep jenkins | grep -v grep
   # 输出示例：
   # jenkins  12345  ...  /usr/bin/java -jar jenkins.war
   # 第一列（jenkins）就是运行 Jenkins 的系统用户名
   
   # 或者查看 systemd 服务配置
   systemctl status jenkins | grep "Main PID"
   
   # 2. 以该用户身份测试 Git 访问（假设是 jenkins 用户）
   sudo -u jenkins git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   
   # 如果失败，说明该系统用户无法访问 Git
   ```

   **解决方法 B：为 Jenkins 系统用户配置 Git**

   ```bash
   # 1. 切换到 Jenkins 系统用户（通常是 jenkins）
   sudo su - jenkins
   
   # 2. 测试 Git 访问
   git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   
   # 3. 如果失败，检查 Git 是否安装
   which git
   git --version
   
   # 4. 如果 Git 未安装，退出 jenkins 用户后安装 Git
   exit  # 退出 jenkins 用户，回到 root 或你的用户
   sudo yum install -y git  # CentOS/RHEL
   # 或
   sudo apt-get install -y git  # Ubuntu/Debian
   
   # 5. 再次以 jenkins 用户身份测试
   sudo -u jenkins git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   ```

   **解决方法 C：检查 Jenkins 网络配置（如果 Jenkins 运行在容器中）**

   ```bash
   # 1. 检查 Jenkins 是否运行在容器中
   docker ps | grep jenkins
   # 或
   systemctl status jenkins
   
   # 2. 如果运行在容器中，进入容器测试
   docker exec -it <jenkins-container-name> git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   
   # 3. 如果容器内无法访问，检查容器网络配置
   docker network inspect <network-name>
   ```

   **解决方法 D：配置 Jenkins Git 插件使用系统 Git**

   **步骤 1：确认系统 Git 路径**

   在服务器上执行：

   ```bash

   # 验证 Git 版本
   git --version
   # 输出类似：git version 2.30.0
   ```

   **步骤 2：检查 Git 插件是否已安装**

   1. 登录 Jenkins Web 界面
   2. 点击 **Manage Jenkins**（管理 Jenkins）
   3. 点击 **Manage Plugins**（管理插件）
   4. 切换到 **Installed**（已安装）标签页
   5. 在搜索框输入 `Git`
   6. 查找 **Git plugin**（Git 插件）
      - 如果已安装，会显示版本号，状态为 "Installed"
      - 如果未安装，切换到 **Available**（可用插件）标签页，搜索并安装 **Git plugin**

   **步骤 3：配置 Git 插件**

   1. 在 Jenkins 主页面，点击 **Manage Jenkins**（管理 Jenkins）
   2. 点击 **Global Tool Configuration**（全局工具配置）
      - 如果找不到，可能在 **Configure Tools**（配置工具）或 **Tools and Locations**（工具和位置）
   3. 在页面中找到 **Git** 部分（通常在页面中下部）
   4. 展开 **Git** 配置区域
   5. 找到 **Git installations**（Git 安装）部分
   6. 点击 **Add Git**（添加 Git）按钮（如果已有 Git 配置，可以编辑现有配置）
   7. 填写配置信息：
      - **Name**（名称）：`Default` 或 `System Git`（可以自定义，用于在 Pipeline 中引用）
      - **Path to Git executable**（Git 可执行文件路径）：
        - 输入系统 Git 路径，例如：`/usr/bin/git`
        - 如果不确定路径，在服务器上执行 `which git` 查看
      - **Default**（默认）：勾选此选项，使其成为默认 Git 安装
   8. 点击 **Save**（保存）或 **Apply**（应用）

   **步骤 4：验证 Git 配置**

   1. 在 **Global Tool Configuration** 页面，确认 Git 配置已保存
   2. 可以创建一个测试 Pipeline 任务验证：
      - 创建新任务 → 选择 Pipeline
      - 在 Pipeline 脚本中测试：

        ```groovy
            agent any

                stage('Test Git') {

                        sh 'git --version'

                }
            }
        }
        ```

   ```groovy

       agent any

       }

               }
           }
       }
   }
   ```

**问题 3.1：首次部署失败 - 部署阶段被跳过**

**症状：**
- Pipeline 执行失败（FAILURE）
- "Deploy to Testing" 和 "Deploy to Production" 阶段显示 `skipped due to earlier failure(s)`
- 错误信息：`ERROR: script returned exit code 1`
- 最后输出：`★ 部署失败!请检查日志。`

**原因分析：**
部署阶段被跳过说明失败发生在更早的阶段，通常是：
1. **Checkout 阶段失败**：无法从 Git 仓库检出代码
2. **Build Application 阶段失败**：Maven 构建失败

**诊断步骤：**

1. **查看完整的构建日志**
   - 在 Jenkins 构建页面，点击 "Console Output"
   - 查看完整的日志输出，找到第一个失败的地方
   - 注意查看是否有红色错误信息

2. **检查 Checkout 阶段**
   ```bash
   # 在日志中查找 "Checkout" 相关错误
   # 常见错误：
   # - "Failed to connect to repository"
   # - "Authentication failed"
   # - "Repository not found"
   ```
   
   **如果 Checkout 失败：**
   - 检查 Git 凭据配置（见问题 1）
   - 检查仓库 URL 是否正确
   - 检查分支名称是否正确（`*/main` 或 `*/develop`）
   - 在服务器上手动测试：`git ls-remote https://github.com/OoForZeroO/mahjong-scoreboard.git HEAD`

3. **检查 Build Application 阶段**
   ```bash
   # 在日志中查找 "Build Application" 或 "mvn" 相关错误
   # 常见错误：
   # - "mvn: command not found"（Maven 未安装）
   # - "JAVA_HOME is not set"（Java 未配置）
   # - "BUILD FAILURE"（Maven 构建失败）
   ```
   
   **如果 Build Application 失败：**

   **A. Maven 未安装或未配置**
   ```bash
   # 在 Jenkins 服务器上检查 Maven
   which mvn
   mvn -version
   
   # 如果 Maven 未安装，需要安装（见 11.1 节）
   # 或配置 Jenkins 使用系统 Maven
   ```
   
   **B. Java 未安装或未配置**
   ```bash
   # 在 Jenkins 服务器上检查 Java
   which java
   java -version
   echo $JAVA_HOME
   
   # 如果 Java 未安装，需要安装 Java 21
   # 如果 JAVA_HOME 未设置，需要在 Jenkinsfile 中设置
   ```
   
   **C. Maven 构建失败（依赖下载失败等）**
   ```bash
   # 查看 Maven 构建的详细错误
   # 在 Jenkins 构建日志中查找具体的错误信息
   # 常见问题：
   # - 网络问题导致依赖下载失败
   # - Maven 仓库配置问题
   # - 代码编译错误
   ```

4. **检查 Jenkins 环境变量**
   - 在 Jenkinsfile 中，`JAVA_HOME` 设置为 `/usr/lib/jvm/java-21-openjdk`
   - 确认该路径在服务器上存在：
     ```bash
     ls -la /usr/lib/jvm/java-21-openjdk
     ```
   - 如果路径不同，需要修改 Jenkinsfile 中的 `JAVA_HOME`

5. **检查 Jenkins 用户权限**
   ```bash
   # 检查 Jenkins 系统用户是否有执行权限
   sudo -u jenkins which mvn
   sudo -u jenkins which java
   sudo -u jenkins mvn -version
   ```

**解决方法：**

1. **如果 Maven 未安装**
   - 按照文档 11.1 节安装 Maven
   - 或在 Jenkins 中配置 Maven 工具（Manage Jenkins → Global Tool Configuration）

2. **如果 Java 未安装或路径错误（JAVA_HOME 未定义）**

   **错误信息：**
   ```
   The JAVA_HOME environment variable is not defined correctly
   This environment variable is needed to run this program
   NB: JAVA_HOME should point to a JDK not a JRE
   ```

   **解决方法 A：检查并确认 Java 路径（推荐）**
   ```bash
   # 在 Jenkins 服务器上执行以下命令查找 Java 路径
   
   # 方法 1：查看已安装的 Java 版本
   ls -la /usr/lib/jvm/
   
   # 方法 2：从 java 命令查找路径
   which java
   readlink -f $(which java)
   # 输出类似：/usr/lib/jvm/java-21-openjdk-amd64/bin/java
   # 那么 JAVA_HOME 应该是：/usr/lib/jvm/java-21-openjdk-amd64
   
   # 方法 3：查看 JAVA_HOME（如果已设置）
   ```

**完整的验证脚本：**

可以创建一个验证脚本，一次性检查所有指标：

```bash
#!/bin/bash
# 服务启动验证脚本

APP_DIR="/opt/yaohufox/production"  # 或 testing
APP_PORT=8081  # 生产环境，测试环境使用 8082
APP_NAME="生产环境"  # 或 "测试环境"

echo "=== 验证 $APP_NAME 服务状态 ==="
echo ""

# 1. 检查 PID 文件
echo "1. 检查进程..."
cd "$APP_DIR"
if [ -f app.pid ]; then
    PID=$(cat app.pid)
    if ps -p $PID > /dev/null 2>&1; then
        echo "   ✅ 进程运行中，PID: $PID"
    else
        echo "   ❌ 进程不存在（PID: $PID）"
        exit 1
    fi
else
    echo "   ❌ PID 文件不存在"
    exit 1
fi

# 2. 检查端口
echo ""
echo "2. 检查端口 $APP_PORT..."
if netstat -tln 2>/dev/null | grep -q ":$APP_PORT " || ss -tln 2>/dev/null | grep -q ":$APP_PORT "; then
    echo "   ✅ 端口 $APP_PORT 正在监听"
else
    echo "   ⚠️  端口 $APP_PORT 未监听"
fi

# 3. HTTP 健康检查
echo ""
echo "3. HTTP 健康检查..."
MAX_RETRIES=5
RETRY_COUNT=0
SUCCESS=false

while [ $RETRY_COUNT -lt $MAX_RETRIES ]; do
    if curl -f -s http://localhost:$APP_PORT/actuator/health > /dev/null 2>&1; then
        echo "   ✅ 健康检查通过"
        curl -s http://localhost:$APP_PORT/actuator/health | python3 -m json.tool 2>/dev/null || curl -s http://localhost:$APP_PORT/actuator/health
        SUCCESS=true
        break
    fi
    RETRY_COUNT=$((RETRY_COUNT + 1))
    if [ $RETRY_COUNT -lt $MAX_RETRIES ]; then
        echo "   ⏳ 等待服务启动... ($RETRY_COUNT/$MAX_RETRIES)"
        sleep 2
    fi
done

if [ "$SUCCESS" != "true" ]; then
    echo "   ❌ 健康检查失败"
    echo ""
    echo "查看应用日志："
    tail -50 "$APP_DIR/app.log"
    exit 1
fi

echo ""
echo "=== $APP_NAME 服务运行正常 ==="
```

保存为 `check-service.sh`，赋予执行权限后运行：

```bash
chmod +x check-service.sh

```

- 应用可能启动失败或未正确启动

**诊断步骤：**

**步骤 0：检查目录和文件（如果没有 app.jar 或 app.log）**

如果目录下没有 `app.jar` 文件，说明 Jenkins 部署过程中 JAR 文件没有被正确复制。这是最严重的问题，需要先解决。

```bash
# 进入生产环境目录
cd /opt/yaohufox/production

# 检查目录内容
echo "=== 目录内容 ==="
ls -la

# 检查关键文件
echo ""
echo "=== 检查关键文件 ==="
[ -f app.jar ] && echo "✅ app.jar 存在 ($(ls -lh app.jar | awk '{print $5}'))" || echo "❌ app.jar 不存在"
[ -f app.pid ] && echo "✅ app.pid 存在: $(cat app.pid)" || echo "❌ app.pid 不存在"
[ -f app.log ] && echo "✅ app.log 存在" || echo "❌ app.log 不存在"
```

**如果 app.jar 不存在，可能的原因：**

1. **Jenkins 构建阶段失败**
   - 查看 Jenkins 构建日志中的 "Build Application" 阶段
   - 检查是否有构建错误

2. **Jenkins 部署阶段失败**
   - 查看 Jenkins 构建日志中的 "Deploy to Production" 阶段
   - 检查是否有 "找不到 JAR 文件" 或 "复制失败" 的错误

3. **部署阶段被跳过**
   - 如果之前的阶段失败，部署阶段会被跳过
   - 检查 Jenkins 构建日志，看是否有阶段被标记为 "skipped"

**解决方法：**

1. **检查 Jenkins 构建日志**
   - 登录 Jenkins Web 界面
   - 进入构建历史，查看最新的构建
   - 点击 "Console Output" 查看完整日志
   - 查找以下关键信息：
     - "构建成功，JAR 文件位置" - 确认构建成功
     - "找到 JAR 文件" - 确认找到了 JAR
     - "JAR 文件复制成功" - 确认复制成功
     - "错误: 找不到 JAR 文件" - 构建失败
     - "错误: 复制失败" - 复制失败

2. **手动检查构建产物**
   ```bash
   # 检查 Jenkins 工作空间（需要 Jenkins 用户权限）
   sudo -u jenkins ls -la /var/lib/jenkins/workspace/mahjong-scoreboard-deploy/mahjong-scoreboard-start/target/
   
   # 或者查找最近的构建产物
   find /var/lib/jenkins/workspace -name "mahjong-scoreboard-start-*.jar" -type f 2>/dev/null | head -5
   ```

3. **手动复制 JAR 文件（临时解决方案）**
   ```bash
   # 如果 Jenkins 工作空间中有 JAR 文件，手动复制
   JAR_FILE=$(find /var/lib/jenkins/workspace/mahjong-scoreboard-deploy/mahjong-scoreboard-start/target -name "mahjong-scoreboard-start-*.jar" -not -name "*-sources.jar" -not -name "*-javadoc.jar" 2>/dev/null | head -1)
   
   if [ -n "$JAR_FILE" ] && [ -f "$JAR_FILE" ]; then
       echo "找到 JAR 文件: $JAR_FILE"
       sudo cp "$JAR_FILE" /opt/yaohufox/production/app.jar
       sudo chown $USER:$USER /opt/yaohufox/production/app.jar
       ls -lh /opt/yaohufox/production/app.jar
   else
       echo "❌ 在 Jenkins 工作空间中也找不到 JAR 文件"
       echo "需要重新构建项目"
   fi
   ```

4. **重新触发 Jenkins 构建**
   - 在 Jenkins 中点击 "立即构建"
   - 确保构建阶段成功完成
   - 确保部署阶段成功执行

**步骤 0.1：检查目录和文件（如果没有 app.log）**

如果目录下没有 `app.log` 文件，说明应用可能根本没有启动。先检查基础文件：


4. **Java 版本不匹配**
   ```bash

   # 应用需要 Java 21
   ```

5. **内存不足**

```bash
#!/bin/bash
# 应用状态诊断脚本

APP_DIR="/opt/yaohufox/production"  # 或 testing
APP_PORT=8081  # 或 8082

echo "=== 应用状态诊断 ==="
echo ""

# 1. 检查目录
echo "1. 检查应用目录..."
if [ -d "$APP_DIR" ]; then
    echo "   ✅ 目录存在: $APP_DIR"

else
    echo "   ❌ 目录不存在: $APP_DIR"
    exit 1
fi

# 2. 检查 JAR 文件
echo ""
echo "2. 检查 JAR 文件..."
if [ -f "$APP_DIR/app.jar" ]; then
    echo "   ✅ JAR 文件存在"
    ls -lh "$APP_DIR/app.jar"
else
    echo "   ❌ JAR 文件不存在"
    exit 1
fi

# 3. 检查进程
echo ""
echo "3. 检查进程..."
if [ -f "$APP_DIR/app.pid" ]; then
    PID=$(cat "$APP_DIR/app.pid")
    echo "   PID 文件中的进程ID: $PID"
    if ps -p $PID > /dev/null 2>&1; then
        echo "   ✅ 进程存在"
        ps aux | grep $PID | grep -v grep
    else
        echo "   ❌ 进程不存在"
    fi
else
    echo "   ⚠️  PID 文件不存在"
fi

# 4. 检查端口
echo ""
echo "4. 检查端口 $APP_PORT..."
if netstat -tln 2>/dev/null | grep -q ":$APP_PORT " || ss -tln 2>/dev/null | grep -q ":$APP_PORT "; then
    echo "   ✅ 端口正在监听"
    netstat -tlnp 2>/dev/null | grep $APP_PORT || ss -tlnp 2>/dev/null | grep $APP_PORT
else
    echo "   ❌ 端口未监听"
fi

# 5. 检查日志
echo ""
echo "5. 最近日志（最后 20 行）："
if [ -f "$APP_DIR/app.log" ]; then
    tail -20 "$APP_DIR/app.log"
else
    echo "   ⚠️  日志文件不存在"
fi

# 6. 检查错误
echo ""
echo "6. 错误信息："
if [ -f "$APP_DIR/app.log" ]; then
    ERRORS=$(grep -i "error\|exception\|failed" "$APP_DIR/app.log" | tail -5)
    if [ -n "$ERRORS" ]; then
        echo "$ERRORS"
    else
        echo "   未发现明显错误"
    fi
fi

echo ""
echo "=== 诊断完成 ==="
```

```groovy
// 验证部署
sh 'sleep 10 && sudo systemctl status mahjong-testing'
```

### 12.5 优缺点对比

**不使用 Docker 的优点：**
- ✅ 不依赖 Docker Hub，避免网络限制
- ✅ 部署更快，不需要构建镜像
- ✅ 资源占用更少
- ✅ 更容易调试

**不使用 Docker 的缺点：**
- ❌ 需要在服务器上安装 Java 和 Maven
- ❌ 环境隔离性较差
- ❌ 不同应用可能冲突
- ❌ 回滚相对复杂

### 12.6 完全自动化部署（无需手动操作服务器）

**重要：** 配置完成后，所有部署操作都可以通过 Jenkins 自动完成，无需手动操作服务器。

**需要的一次性服务器配置（只需配置一次）：**

1. **安装 Java 和 Maven**（见 11.1 节）
2. **创建应用目录**（见 11.1 节）
3. **配置 systemd 服务**（见 11.4 节，推荐）
4. **配置 Jenkins 用户权限**（见下方）

**Jenkins 可以自动完成的操作：**

- ✅ 检出代码
- ✅ 构建应用（Maven）
- ✅ 停止旧应用
- ✅ 复制新的 JAR 文件
- ✅ 启动新应用
- ✅ 验证部署
- ✅ 清理旧构建产物

**配置 Jenkins 用户权限（一次性操作）：**

```bash
# 1. 确保 Jenkins 用户有权限操作应用目录
sudo chown -R jenkins:jenkins /opt/yaohufox/{production,testing}

# 2. 如果使用 systemd，配置 sudo 权限（可选，更安全）
# 创建 sudoers 配置，允许 Jenkins 用户管理服务
sudo tee /etc/sudoers.d/jenkins > /dev/null <<EOF
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl start mahjong-production
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl stop mahjong-production
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl restart mahjong-production
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl status mahjong-production
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl start mahjong-testing
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl stop mahjong-testing
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl restart mahjong-testing
jenkins ALL=(ALL) NOPASSWD: /bin/systemctl status mahjong-testing
EOF

# 3. 验证权限
sudo -u jenkins ls -la /opt/yaohufox/production
sudo -u jenkins ls -la /opt/yaohufox/testing
```

**使用 systemd 的完全自动化 Jenkinsfile：**

如果配置了 systemd 服务，Jenkinsfile 可以更简洁和稳定：

```groovy
stage('Deploy to Testing') {
    when {
        anyOf {
            branch 'develop'
            branch 'test'
        }
    }
    steps {
        script {
            dir(TESTING_DIR) {
                echo "开始部署到测试环境..."
                
                // 停止旧应用（使用 systemd）
                sh 'sudo systemctl stop mahjong-testing || true'
                
                // 复制新的 JAR 文件
                sh '''
                    mkdir -p ${TESTING_DIR}
                    cp ${WORKSPACE}/mahjong-scoreboard-start/target/mahjong-scoreboard-start-*.jar ${TESTING_DIR}/app.jar
                '''
                
                // 启动新应用（使用 systemd）
                sh 'sudo systemctl start mahjong-testing'
                
                // 等待并验证
                sh 'sleep 10 && sudo systemctl status mahjong-testing'
                
                echo "测试环境部署完成！"
            }
        }
    }
}
```

**部署流程对比：**

| 操作 | Docker 部署 | 不使用 Docker（当前） | 不使用 Docker（systemd） |
|------|------------|---------------------|------------------------|
| 构建镜像 | ✅ 自动 | ❌ 不需要 | ❌ 不需要 |
| 构建应用 | ✅ 自动 | ✅ 自动 | ✅ 自动 |
| 停止旧应用 | ✅ 自动（docker-compose） | ✅ 自动（PID 文件） | ✅ 自动（systemd） |
| 启动新应用 | ✅ 自动（docker-compose） | ✅ 自动（nohup） | ✅ 自动（systemd） |
| 验证部署 | ✅ 自动 | ✅ 自动 | ✅ 自动 |
| 需要手动操作 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 |

**总结：**

- ✅ **可以完全不操作服务器**：配置完成后，所有操作都通过 Jenkins 自动完成
- ✅ **一次性配置**：只需在服务器上配置一次（Java、Maven、目录、systemd）
- ✅ **后续完全自动化**：代码提交后，Jenkins 自动构建和部署
- ✅ **推荐使用 systemd**：更稳定、更可靠、支持自动重启

### 12.7 切换回 Docker 部署

如果后续解决了 Docker Hub 访问问题，可以：

1. 手动导入基础镜像（参考前面的步骤）
2. 恢复使用原来的 `Jenkinsfile`
3. 重新配置 Docker Compose

**完成！** 按照以上步骤，你的服务器环境就搭建完成了。所有配置都遵循你的目录结构，Jenkins 配置完全隔离，不会污染现有配置。如有问题，请查看对应章节的详细说明。

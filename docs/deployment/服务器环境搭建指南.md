# 阿里云服务器环境搭建指南

## 一、服务器目录结构设计

### 1.1 创建基础目录结构

在服务器上执行以下命令创建目录：

```bash
# 进入项目目录
cd /opt

# 创建主目录结构
sudo mkdir -p yaohufox/{config,certificates,data,logs,scripts}

# 创建配置目录
sudo mkdir -p yaohufox/config/{nginx,jenkins}
sudo mkdir -p yaohufox/config/nginx/{sites-available,sites-enabled}

# 创建证书目录
sudo mkdir -p yaohufox/certificates/{prod,test,jenkins}

# 创建数据目录
sudo mkdir -p yaohufox/data/{postgres-prod,postgres-test,jenkins}

# 创建日志目录
sudo mkdir -p yaohufox/logs/{nginx,postgres,app}

# 创建应用目录（生产环境和测试环境）
sudo mkdir -p yaohufox/{production,testing}

# 设置权限（使用你的用户名替换 your_username）
sudo chown -R your_username:your_username /opt/yaohufox
```

**目录说明：**
- `config/` - 配置文件（Nginx、Jenkins 分离，避免污染）
- `certificates/` - SSL 证书（生产、测试、Jenkins 分离）
- `data/` - 持久化数据（数据库、Jenkins 数据）
- `logs/` - 日志文件（按服务分类）
- `scripts/` - 运维脚本
- `production/` - 生产环境应用
- `testing/` - 测试环境应用

## 二、Docker 环境准备

### 2.1 安装 Docker 和 Docker Compose

```bash
# 更新系统
sudo yum update -y

# 安装 Docker
sudo yum install -y docker

# 启动 Docker 服务
sudo systemctl start docker
sudo systemctl enable docker

# 安装 Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# 验证安装
docker --version
docker-compose --version
```

### 2.2 配置 Docker 用户组（避免每次使用 sudo）

```bash
# 将当前用户添加到 docker 组
sudo usermod -aG docker $USER

# 重新登录或执行以下命令使组生效
newgrp docker

# 验证（应该不需要 sudo）
docker ps
```

## 三、PostgreSQL 数据库配置

### 3.1 创建生产环境数据库配置

创建文件：`/opt/yaohufox/production/docker-compose.yml`

**注意：** 新版本的 Docker Compose 不再需要 `version` 字段，直接省略即可。

```yaml
services:
  postgresql-prod:
    image: postgres:15-alpine
    container_name: yaohufox-postgres-prod
    restart: always
    environment:
      POSTGRES_DB: mahjong_score_system
      POSTGRES_USER: mahjong_user
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}  # 从环境变量读取
      PGDATA: /var/lib/postgresql/data/pgdata
    ports:
      - "127.0.0.1:5432:5432"  # 只允许本地连接
    volumes:
      - /opt/yaohufox/data/postgres-prod:/var/lib/postgresql/data
      - /opt/yaohufox/config/postgres-init-prod.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - yaohufox-network-prod
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U mahjong_user -d mahjong_score_system"]
      interval: 10s
      timeout: 5s
      retries: 5
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"

  mahjong-app-prod:
    image: mahjong-scoreboard:latest  # Jenkins 构建的镜像
    container_name: yaohufox-app-prod
    restart: always
    ports:
      - "127.0.0.1:8081:8080"  # 映射到 8081，只允许本地访问
    environment:
      - SPRING_PROFILES_ACTIVE=production
      - SPRING_DATASOURCE_URL=jdbc:postgresql://postgresql-prod:5432/mahjong_score_system
      - SPRING_DATASOURCE_USERNAME=mahjong_user
      - SPRING_DATASOURCE_PASSWORD=${POSTGRES_PASSWORD}
      - SERVER_PORT=8080
      - WECHAT_APPID=${WECHAT_APPID}
      - WECHAT_APPSECRET=${WECHAT_APPSECRET}
    volumes:
      - /opt/yaohufox/logs/app/production:/app/logs
    depends_on:
      postgresql-prod:
        condition: service_healthy
    networks:
      - yaohufox-network-prod
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"

networks:
  yaohufox-network-prod:
    driver: bridge
```

### 3.5 启动数据库和应用

**重要提示：** 首次部署时，应用镜像 `mahjong-scoreboard:latest` 还不存在（需要通过 Jenkins 构建），所以建议分步启动：

**第一步：只启动数据库（生产环境）**
```bash
cd /opt/yaohufox/production
docker-compose --env-file .env up -d postgresql-prod
```

**第二步：只启动数据库（测试环境）**
```bash
cd /opt/yaohufox/testing
```

**第三步：等待 Jenkins 构建应用镜像**
- 在 Jenkins 中触发构建任务
- 等待构建完成

**第四步：启动应用服务**
```bash
# 生产环境
cd /opt/yaohufox/production
docker-compose --env-file .env up -d

# 测试环境
cd /opt/yaohufox/testing
docker-compose --env-file .env up -d
```

**如果应用镜像已存在，可以直接启动所有服务：**

```bash
docker-compose --env-file .env up -d
```

## 四、Nginx 反向代理配置

### 4.1 安装 Nginx

```bash
sudo yum install -y nginx

# 启动 Nginx
sudo systemctl start nginx
sudo systemctl enable nginx
```

### 4.2 配置生产环境反向代理

**创建配置文件：**

```bash
sudo vi /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf
```

将以下内容写入文件：

```nginx
# 生产环境配置 - yaohufox.com
upstream mahjong_production {
    server 127.0.0.1:8081;  # Spring Boot 应用端口
}

server {
    listen 80;
    server_name yaohufox.com www.yaohufox.com;
    
    # 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yaohufox.com www.yaohufox.com;

    # SSL 证书配置
    ssl_certificate /opt/yaohufox/certificates/prod/fullchain.pem;
    ssl_certificate_key /opt/yaohufox/certificates/prod/privkey.pem;
    
    # SSL 优化配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 日志
    access_log /opt/yaohufox/logs/nginx/production-access.log;
    error_log /opt/yaohufox/logs/nginx/production-error.log;

    # 客户端上传大小限制
    client_max_body_size 10M;

    # API 代理
    location / {
        proxy_pass http://mahjong_production;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket 支持（如果需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 健康检查端点
    location /health {
        proxy_pass http://mahjong_production/actuator/health;
        access_log off;
    }
}
```

### 4.4 启用 Nginx 配置

**首先验证配置文件是否存在：**

```bash
# 检查配置文件是否已创建
ls -la /opt/yaohufox/config/nginx/sites-available/

# 应该看到：
# mahjong-production.conf
# mahjong-testing.conf
```

**创建符号链接启用配置：**

```bash
# 确保 sites-enabled 目录存在
sudo mkdir -p /opt/yaohufox/config/nginx/sites-enabled

# 创建符号链接启用配置
sudo ln -s /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf /opt/yaohufox/config/nginx/sites-enabled/
sudo ln -s /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf /opt/yaohufox/config/nginx/sites-enabled/

# 验证符号链接是否创建成功
ls -la /opt/yaohufox/config/nginx/sites-enabled/

# 应该看到指向配置文件的符号链接
```

**在 Nginx 主配置文件中包含 sites-enabled：**

```bash
sudo vi /etc/nginx/nginx.conf
```

在 `http {` 块中添加：
```nginx
include /opt/yaohufox/config/nginx/sites-enabled/*.conf;
```

**验证主配置文件：**

```bash
# 检查 include 语句是否正确添加
grep -n "sites-enabled" /etc/nginx/nginx.conf

# 应该看到类似这样的输出：
# 32:    include /opt/yaohufox/config/nginx/sites-enabled/*.conf;
```

### 4.4.1 故障排除：Nginx 配置验证失败

**如果执行 `sudo nginx -t` 时出现 "No such file or directory" 错误，请按以下步骤诊断和修复：**

**步骤 1：完整诊断脚本**

```bash
#!/bin/bash
echo "=== Nginx 配置诊断 ==="
echo ""

echo "1. 检查目录结构："
echo "   /opt/yaohufox/config/nginx/sites-available/"
ls -la /opt/yaohufox/config/nginx/sites-available/ 2>/dev/null || echo "   ❌ 目录不存在或为空"
echo ""

echo "2. 检查符号链接："
echo "   /opt/yaohufox/config/nginx/sites-enabled/"
ls -la /opt/yaohufox/config/nginx/sites-enabled/ 2>/dev/null || echo "   ❌ 目录不存在或为空"
echo ""

echo "3. 检查主配置文件："
grep -n "sites-enabled" /etc/nginx/nginx.conf 2>/dev/null || echo "   ❌ include 语句未找到"
echo ""

echo "4. 检查配置文件内容："
if [ -f /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf ]; then
    echo "   ✅ mahjong-production.conf 存在"
    head -5 /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf
else
    echo "   ❌ mahjong-production.conf 不存在"
fi
echo ""

if [ -f /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf ]; then
    echo "   ✅ mahjong-testing.conf 存在"
    head -5 /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf
else
    echo "   ❌ mahjong-testing.conf 不存在"
fi
```

### 4.6 配置 Jenkins 反向代理

**重要：** Jenkins 需要单独的 Nginx 配置和 SSL 证书。

**步骤 1：创建 Jenkins Nginx 配置文件**


```nginx
# Jenkins 配置 - jenkins.yaohufox.com
upstream jenkins_backend {
    server 127.0.0.1:8080;  # Jenkins 默认端口（根据实际 Jenkins 端口调整）
}

server {
    listen 80;
    server_name jenkins.yaohufox.com;
    
    # 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name jenkins.yaohufox.com;

    # SSL 证书配置
    ssl_certificate /opt/yaohufox/certificates/jenkins/fullchain.pem;
    ssl_certificate_key /opt/yaohufox/certificates/jenkins/privkey.pem;
    
    # SSL 优化配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 日志
    access_log /opt/yaohufox/logs/nginx/jenkins-access.log;
    error_log /opt/yaohufox/logs/nginx/jenkins-error.log;

    # Jenkins 需要较大的上传限制（用于上传构建产物）
    client_max_body_size 100M;

    # Jenkins 代理配置
    location / {
        proxy_pass http://jenkins_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket 支持（Jenkins 需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # 超时设置（Jenkins 构建可能需要较长时间）
        proxy_connect_timeout 300s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;
        
        # Jenkins 特定配置
        proxy_redirect http:// https://;
    }
}
```

### 4.6.1 Jenkins SSL 证书故障排除

**方法 1：检查证书域名**


**方法 2：临时使用自签名证书（仅用于测试）**

```bash
# 生成自签名证书（仅用于测试，浏览器会显示警告）
sudo mkdir -p /opt/yaohufox/certificates/jenkins
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /opt/yaohufox/certificates/jenkins/privkey.pem \
  -out /opt/yaohufox/certificates/jenkins/fullchain.pem \
  -subj "/C=CN/ST=State/L=City/O=Organization/CN=jenkins.yaohufox.com"

sudo chmod 600 /opt/yaohufox/certificates/jenkins/privkey.pem
sudo chmod 644 /opt/yaohufox/certificates/jenkins/fullchain.pem

# 重启 Nginx
sudo systemctl reload nginx
```

**注意：** 自签名证书会导致浏览器显示安全警告，需要点击「高级」→「继续访问」才能进入。生产环境请使用正式证书。

   1. 登录 GitHub：https://github.com
   2. 点击右上角头像 → **Settings**
   3. 左侧菜单选择 **Developer settings**
   4. 选择 **Personal access tokens** → **Tokens (classic)**

   8. **重要：** 立即复制生成的 token（只显示一次），格式类似：`ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

   7. 填写凭据信息：
      - **Kind**（类型）：选择 `Username with password`

      - **Username**（用户名）：输入你的 GitHub 用户名
      - **Password**（密码）：粘贴刚才复制的 Personal Access Token（不是 GitHub 密码）
      - **ID**（唯一标识）：留空（Jenkins 会自动生成）或填写 `github-token`
      - **Description**（描述）：`GitHub Personal Access Token`
   8. 点击 **Create**（创建）或 **确定**

   1. 在 Jenkins 主页面，点击 **Manage Jenkins**（管理 Jenkins）
   2. 选择 **Manage Credentials**（管理凭据）

      - 点击凭据查看详情
      - 确认 **Kind**（类型）是 `Username with password`，不是其他类型

   2. **重新创建凭据（推荐）**
      - 删除现有凭据（如果可能）
      - 按照步骤 3.2 重新创建凭据，确保：
        - **Kind**：选择 `Username with password`
        - **Username**：你的 GitHub 用户名（不是邮箱）

        - **Secret**：粘贴完整的 Personal Access Token
        - **ID**：填写 `github-token`
        - **Description**：`GitHub Personal Access Token`

   6. **检查 Jenkins 凭据插件**

**问题 1：Failed to setup credentials（凭据设置失败）**

**症状：**

- 已经选择了凭据（显示为 `OoForZeroO/******`），但仍然报错
- 凭据在凭据管理页面中显示正常

**解决方法：**

1. **检查凭据类型**
   - 进入 **Manage Jenkins** → **Manage Credentials**
   - 找到你使用的凭据，点击查看详情
   - 确认 **Kind**（类型）是 `Username with password`
   - 如果类型不对，删除并重新创建

2. **验证 Token 是否有效**
   ```bash
   # 在服务器上测试 Token（替换 YOUR_USERNAME 和 YOUR_TOKEN）
   git ls-remote https://YOUR_USERNAME:YOUR_TOKEN@github.com/OoForZeroO/mahjong-scoreboard.git HEAD
   
   # 如果失败，说明 Token 无效、过期或权限不足
   ```

3. **重新创建凭据（推荐）**
   - 删除现有凭据
   - 创建新凭据，确保：
     - **Kind**：`Username with password`
     - **Username**：GitHub 用户名（不是邮箱，例如：`OoForZeroO`）
     - **Password**：完整的 Personal Access Token（以 `ghp_` 开头，例如：`ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
     - 确保 Token 没有多余空格或换行
   - 保存后，在 Pipeline 配置中重新选择新凭据

4. **检查 Token 权限和状态**
   - 访问：https://github.com/settings/tokens
   - 找到你使用的 Token
   - 确认状态为 "Active"（活跃）
   - 确认有 `repo` scope（权限）
   - 如果 Token 已过期或被撤销，创建新 Token

5. **尝试使用 Secret text 类型**
   如果 `Username with password` 类型不工作：
   - 创建新凭据，**Kind** 选择 `Secret text`
   - **Secret**：粘贴完整的 Personal Access Token
   - **ID**：`github-token`
   - **Description**：`GitHub Personal Access Token`
   - 在 Pipeline 配置中选择这个凭据

6. **检查 Jenkins 凭据插件**
   - **Manage Jenkins** → **Manage Plugins** → **Installed**
   - 确认 **Credentials Plugin** 已安装且为最新版本
   - 如果没有，安装并重启 Jenkins

7. **清除 Jenkins 缓存**
   ```bash

   sudo systemctl stop jenkins
   sudo rm -rf /var/lib/jenkins/cache/*
   sudo systemctl start jenkins
   ```

   ```bash

   which git
   git --version
   
   # 4. 如果 Git 未安装，退出 jenkins 用户后安装 Git

   # 或
   sudo apt-get install -y git  # Ubuntu/Debian
   ```

**问题 4：Docker 构建失败 - DNS 解析错误（no such host）**

**症状：**
- 错误信息：`dial tcp: lookup docker.mirrors.ustc.edu.cn on 127.0.0.53:53: no such host`
- 或：`failed to resolve source metadata for docker.io/library/maven:3.9-eclipse-temurin-21`
- Docker 无法解析镜像加速器域名

**解决方法：**

1. **诊断 DNS 问题**

   ```bash
   # 测试 DNS 解析
   nslookup docker.mirrors.ustc.edu.cn
   dig docker.mirrors.ustc.edu.cn
   
   # 如果失败，检查 DNS 配置
   cat /etc/resolv.conf
   ```

2. **修复 DNS 配置**

   ```bash
   # 方法 1：添加公共 DNS 服务器
   sudo tee /etc/resolv.conf > /dev/null <<EOF
   nameserver 8.8.8.8
   nameserver 114.114.114.114
   nameserver 223.5.5.5
   EOF
   
   # 方法 2：如果使用 systemd-resolved
   sudo systemd-resolve --flush-caches
   sudo systemctl restart systemd-resolved
   
   # 方法 3：测试 DNS 解析
   nslookup docker.mirrors.ustc.edu.cn
   ```

3. **移除有问题的镜像加速器配置**

   ```bash
   # 如果 DNS 问题无法解决，移除镜像加速器配置
   sudo tee /etc/docker/daemon.json > /dev/null <<EOF
   {
     "registry-mirrors": []
   }
   EOF
   
   # 或者使用可用的镜像加速器
   sudo tee /etc/docker/daemon.json > /dev/null <<EOF
   {
     "registry-mirrors": [
       "https://mirror.ccs.tencentyun.com"
     ]
   }
   EOF
   
   # 重启 Docker
   sudo systemctl daemon-reload
   sudo systemctl restart docker
   
   # 验证配置
   docker info | grep -A 10 "Registry Mirrors"
   ```

4. **测试镜像拉取**

   ```bash
   # 测试拉取基础镜像
   docker pull maven:3.9-eclipse-temurin-21
   docker pull eclipse-temurin:21-jre-alpine
   ```

   ```bash
   # 6. 查看 Docker 日志，确认使用的镜像源
   sudo journalctl -u docker -f
   # 在另一个终端执行 docker pull，观察日志
   
   # 7. 如果日志显示仍然访问 registry-1.docker.io，说明镜像加速器未生效
   # 可能的原因：
   # - 镜像加速器不支持该镜像或标签
   # - Docker 在某些情况下会回退到 Docker Hub
   # - 需要手动导入镜像

   # 这是常见问题，镜像加速器可能未同步某些镜像或标签
   # 解决方案：手动导入镜像（见下面的详细步骤）
   ```

   **如果镜像加速器配置已生效但仍无法拉取镜像，使用手动导入方案：**

   ```bash

   nameserver 8.8.8.8
   nameserver 114.114.114.114
   nameserver 223.5.5.5
   EOF
   
   # 方法 4：如果使用 NetworkManager，配置 DNS
   sudo nmcli connection modify <connection-name> ipv4.dns "8.8.8.8 114.114.114.114"
   sudo systemctl restart NetworkManager
   ```

### 11.3 配置应用启动脚本（可选）

```bash
APP_DIR=$1
```

### 11.4 配置 systemd 服务（推荐，更稳定）

创建 systemd 服务文件，实现自动启动和重启：

```bash
# 创建生产环境服务
sudo tee /etc/systemd/system/mahjong-production.service > /dev/null <<EOF
[Unit]
Description=Mahjong Scoreboard Production
After=network.target postgresql.service

[Service]
Type=simple
User=your-username
WorkingDirectory=/opt/yaohufox/production
ExecStart=/usr/bin/java -jar -Dspring.profiles.active=production /opt/yaohufox/production/app.jar
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

# 创建测试环境服务
sudo tee /etc/systemd/system/mahjong-testing.service > /dev/null <<EOF
[Unit]
Description=Mahjong Scoreboard Testing
After=network.target postgresql.service

[Service]
Type=simple
User=your-username
WorkingDirectory=/opt/yaohufox/testing
ExecStart=/usr/bin/java -jar -Dspring.profiles.active=testing /opt/yaohufox/testing/app.jar
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

# 重新加载 systemd
sudo systemctl daemon-reload

# 启用服务（可选，开机自启）
sudo systemctl enable mahjong-production
sudo systemctl enable mahjong-testing
```

在 Jenkinsfile 中使用 systemd 管理：

```groovy
// 停止旧应用

// 复制新的 JAR 文件

// 验证部署

```

### 11.5 优缺点对比

**不使用 Docker 的优点：**
- ✅ 不依赖 Docker Hub，避免网络限制
- ✅ 部署更快，不需要构建镜像
- ✅ 资源占用更少
- ✅ 更容易调试

**不使用 Docker 的缺点：**
- ❌ 需要在服务器上安装 Java 和 Maven
- ❌ 环境隔离性较差
- ❌ 不同应用可能冲突
- ❌ 回滚相对复杂

### 11.6 切换回 Docker 部署

如果后续解决了 Docker Hub 访问问题，可以：

1. 手动导入基础镜像（参考前面的步骤）
2. 恢复使用原来的 `Jenkinsfile`
3. 重新配置 Docker Compose

**完成！** 按照以上步骤，你的服务器环境就搭建完成了。所有配置都遵循你的目录结构，Jenkins 配置完全隔离，不会污染现有配置。如有问题，请查看对应章节的详细说明。

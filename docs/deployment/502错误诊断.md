# 502 Bad Gateway 错误诊断指南

## 问题说明

502 Bad Gateway 错误表示 Nginx 作为反向代理无法连接到后端 Spring Boot 应用。

## 快速诊断步骤

### 步骤 1: 检查应用是否运行

```bash
# 检查生产环境进程
ps aux | grep java | grep app.jar

# 检查 PID 文件
if [ -f /opt/yaohufox/production/app.pid ]; then
    PID=$(cat /opt/yaohufox/production/app.pid)
    echo "PID 文件中的进程 ID: $PID"
    if ps -p $PID > /dev/null 2>&1; then
        echo "✅ 应用进程正在运行 (PID: $PID)"
    else
        echo "❌ 应用进程不存在 (PID: $PID)"
    fi
else
    echo "❌ PID 文件不存在，应用可能未启动"
fi
```

### 步骤 2: 检查端口是否监听

```bash
# 检查生产环境端口 8081
echo "检查端口 8081（生产环境）:"
netstat -tln | grep ":8081 " || ss -tln | grep ":8081 "

# 检查测试环境端口 8082
echo "检查端口 8082（测试环境）:"
netstat -tln | grep ":8082 " || ss -tln | grep ":8082 "
```

### 步骤 3: 直接访问应用（绕过 Nginx）

```bash
# 直接访问生产环境应用
curl http://localhost:8081/api/test/hello

# 直接访问测试环境应用
curl http://localhost:8082/api/test/hello
```

### 步骤 4: 检查应用日志

```bash
# 查看生产环境最新日志
echo "=== 生产环境最新日志（最后 50 行）==="
tail -50 /opt/yaohufox/production/app.log

# 查看错误日志
echo "=== 生产环境错误日志 ==="
tail -100 /opt/yaohufox/production/app.log | grep -i error
```

### 步骤 5: 检查 Nginx 配置

```bash
# 检查 Nginx 配置中的 upstream 地址
echo "=== 生产环境 Nginx 配置 ==="
grep -A 2 "upstream mahjong_production" /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf

echo "=== 测试环境 Nginx 配置 ==="
grep -A 2 "upstream mahjong_testing" /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf
```

### 步骤 6: 检查 Nginx 错误日志

```bash
# 查看 Nginx 错误日志
echo "=== Nginx 错误日志（最后 20 行）==="
tail -20 /opt/yaohufox/logs/nginx/production-error.log
tail -20 /opt/yaohufox/logs/nginx/testing-error.log
```

## 完整诊断脚本

将以下脚本保存为 `diagnose-502.sh` 并执行：

```bash
#!/bin/bash

echo "=========================================="
echo "502 Bad Gateway 错误诊断"
echo "=========================================="
echo ""

# 1. 检查应用进程
echo "1. 检查应用进程状态..."
echo "   - 生产环境:"
if [ -f /opt/yaohufox/production/app.pid ]; then
    PID=$(cat /opt/yaohufox/production/app.pid)
    if ps -p $PID > /dev/null 2>&1; then
        echo "   ✅ 进程运行中 (PID: $PID)"
    else
        echo "   ❌ 进程不存在 (PID: $PID)"
    fi
else
    echo "   ❌ PID 文件不存在"
fi

echo "   - 测试环境:"
if [ -f /opt/yaohufox/testing/app.pid ]; then
    PID=$(cat /opt/yaohufox/testing/app.pid)
    if ps -p $PID > /dev/null 2>&1; then
        echo "   ✅ 进程运行中 (PID: $PID)"
    else
        echo "   ❌ 进程不存在 (PID: $PID)"
    fi
else
    echo "   ❌ PID 文件不存在"
fi

echo ""

# 2. 检查端口监听
echo "2. 检查端口监听状态..."
echo "   - 端口 8081（生产环境）:"
if netstat -tln 2>/dev/null | grep -q ":8081 " || ss -tln 2>/dev/null | grep -q ":8081 "; then
    echo "   ✅ 端口 8081 正在监听"
else
    echo "   ❌ 端口 8081 未监听"
fi

echo "   - 端口 8082（测试环境）:"
if netstat -tln 2>/dev/null | grep -q ":8082 " || ss -tln 2>/dev/null | grep -q ":8082 "; then
    echo "   ✅ 端口 8082 正在监听"
else
    echo "   ❌ 端口 8082 未监听"
fi

echo ""

# 3. 直接访问应用
echo "3. 直接访问应用（绕过 Nginx）..."
echo "   - 生产环境 (localhost:8081):"
if curl -f -s http://localhost:8081/api/test/hello > /dev/null 2>&1; then
    echo "   ✅ 应用响应正常: $(curl -s http://localhost:8081/api/test/hello)"
else
    echo "   ❌ 应用无响应"
fi

echo "   - 测试环境 (localhost:8082):"
if curl -f -s http://localhost:8082/api/test/hello > /dev/null 2>&1; then
    echo "   ✅ 应用响应正常: $(curl -s http://localhost:8082/api/test/hello)"
else
    echo "   ❌ 应用无响应"
fi

echo ""

# 4. 检查应用日志
echo "4. 检查应用日志（最后 10 行）..."
echo "   - 生产环境日志:"
tail -10 /opt/yaohufox/production/app.log 2>/dev/null || echo "   ⚠️  日志文件不存在或无法读取"

echo ""

# 5. 检查 Nginx 配置
echo "5. 检查 Nginx upstream 配置..."
echo "   - 生产环境 upstream:"
grep -A 1 "upstream mahjong_production" /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf 2>/dev/null || echo "   ⚠️  配置文件不存在"

echo "   - 测试环境 upstream:"
grep -A 1 "upstream mahjong_testing" /opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf 2>/dev/null || echo "   ⚠️  配置文件不存在"

echo ""

# 6. 检查 Nginx 错误日志
echo "6. 检查 Nginx 错误日志（最后 5 行）..."
echo "   - 生产环境 Nginx 错误:"
tail -5 /opt/yaohufox/logs/nginx/production-error.log 2>/dev/null || echo "   ⚠️  日志文件不存在"

echo ""

echo "=========================================="
echo "诊断完成"
echo "=========================================="
```

## 常见问题及解决方案

### 问题 1: 应用进程不存在

**症状**: PID 文件不存在或进程已退出

**解决方案**:
```bash
# 检查应用日志，找出启动失败的原因
tail -100 /opt/yaohufox/production/app.log

# 手动启动应用（用于调试）
cd /opt/yaohufox/production
nohup java -jar -Dspring.profiles.active=production -Dserver.port=8081 app.jar > app.log 2>&1 &
echo $! > app.pid
```

### 问题 2: 端口未监听

**症状**: 应用进程存在但端口未监听

**可能原因**:
- 应用启动失败
- 端口被其他程序占用
- 应用配置的端口不对

**解决方案**:
```bash
# 检查端口占用
sudo lsof -i :8081
sudo lsof -i :8082

# 检查应用配置的端口
grep "server.port" /opt/yaohufox/production/app.jar  # 这不会工作，需要查看配置文件
# 或者查看启动命令中的端口参数
```

### 问题 3: 应用启动失败

**症状**: 应用进程立即退出，日志中有错误信息

**常见错误**:
1. **数据库连接失败**
   ```
   FATAL: password authentication failed
   ```
   解决: 检查 `.env` 文件中的数据库密码

2. **表结构验证失败**
   ```
   Schema-validation: missing column [id]
   ```
   解决: 执行数据库初始化脚本

3. **Repository 未找到**
   ```
   No qualifying bean of type 'com.mahjong.repository.UserRepository'
   ```
   解决: 确保主应用类有 `@EnableJpaRepositories` 注解

**解决方案**:
```bash
# 查看完整错误日志
tail -200 /opt/yaohufox/production/app.log | grep -A 10 -i error

# 根据错误信息修复问题后重新启动
```

### 问题 4: Nginx upstream 配置错误

**症状**: 应用正常运行，但 Nginx 无法连接

**检查**:
```bash
# 检查 Nginx 配置中的 upstream 地址
cat /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf | grep -A 2 upstream

# 应该看到：
# upstream mahjong_production {
#     server 127.0.0.1:8081;
# }
```

**解决方案**:
```bash
# 如果配置错误，修改配置文件
sudo vi /opt/yaohufox/config/nginx/sites-available/mahjong-production.conf

# 确保 upstream 指向正确的端口：
# upstream mahjong_production {
#     server 127.0.0.1:8081;  # 生产环境
# }

# 重新加载 Nginx 配置
sudo nginx -t  # 测试配置
sudo systemctl reload nginx  # 重新加载
```

### 问题 5: 防火墙阻止连接

**症状**: 应用和 Nginx 都正常，但无法连接

**解决方案**:
```bash
# 检查防火墙状态
sudo ufw status

# 如果需要，允许端口（通常不需要，因为都是本地连接）
# sudo ufw allow 8081
# sudo ufw allow 8082
```

## 快速修复命令

### 如果应用未启动，手动启动

```bash
# 生产环境
cd /opt/yaohufox/production
nohup java -jar -Dspring.profiles.active=production -Dserver.port=8081 app.jar > app.log 2>&1 &
echo $! > app.pid

# 测试环境
cd /opt/yaohufox/testing
nohup java -jar -Dspring.profiles.active=testing -Dserver.port=8082 app.jar > app.log 2>&1 &
echo $! > app.pid
```

### 如果应用启动失败，查看日志

```bash
# 查看完整启动日志
tail -200 /opt/yaohufox/production/app.log

# 查找错误
grep -i "error\|exception\|failed" /opt/yaohufox/production/app.log | tail -20
```

### 如果 Nginx 配置有问题，重新加载

```bash
# 测试配置
sudo nginx -t

# 重新加载
sudo systemctl reload nginx
```

## 验证修复

修复后，使用以下命令验证：

```bash
# 1. 直接访问应用
curl http://localhost:8081/api/test/hello

# 2. 通过 Nginx 访问
curl https://yaohufox.com/api/test/hello

# 3. 检查健康状态
curl http://localhost:8081/actuator/health
```

## 总结

502 错误的常见原因（按频率排序）：
1. **应用未启动** - 最常见
2. **应用启动失败** - 查看日志找出原因
3. **端口配置错误** - 检查应用端口和 Nginx upstream
4. **Nginx 配置错误** - 检查 upstream 地址

按照上述步骤逐一排查，通常能找到问题所在。

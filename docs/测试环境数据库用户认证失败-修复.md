# 测试环境数据库用户认证失败 — 修复指南

## 错误说明

启动时出现：

```text
org.postgresql.util.PSQLException: FATAL: password authentication failed for user "yaohu"
```

表示应用尝试用 PostgreSQL 用户 `yaohu` 连接数据库，但密码认证失败。

---

## 快速诊断（在服务器上执行）

SSH 登录测试环境服务器后，按顺序执行：

### 1. 检查用户是否存在

```bash
sudo -u postgres psql -c "\du yaohu"
```

**结果判断**：
- 有输出 → 用户存在，跳到步骤 2
- 无输出 → 用户不存在，需要创建（见下方「创建用户」）

### 2. 测试用户密码（如果用户存在）

```bash
# 尝试用默认密码连接
PGPASSWORD=cch815566 psql -h localhost -U yaohu -d mahjong_scoreboard_system_test -c "SELECT 1;"
```

**结果判断**：
- 成功 → 密码正确，问题可能在应用配置
- 失败 → 密码错误，需要重置密码（见下方「重置密码」）

### 3. 检查用户权限

```bash
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "\dn"
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "\dp"
```

---

## 修复方案

### 方案一：创建用户并设置密码（用户不存在时）

```bash
# 1. 创建用户并设置密码
sudo -u postgres psql -c "CREATE USER yaohu WITH PASSWORD 'cch815566';"

# 2. 授予数据库权限
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE mahjong_scoreboard_system_test TO yaohu;"

# 3. 授予 schema 权限
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "GRANT ALL ON SCHEMA public TO yaohu;"

# 4. 授予表权限（如果表已存在）
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO yaohu;"
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO yaohu;"

# 5. 设置默认权限（新创建的表自动授权）
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO yaohu;"
sudo -u postgres psql -d mahjong_scoreboard_system_test -c "ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO yaohu;"
```

### 方案二：重置密码（用户存在但密码错误）

```bash
# 重置密码为默认值
sudo -u postgres psql -c "ALTER USER yaohu WITH PASSWORD 'cch815566';"

# 验证新密码
PGPASSWORD=cch815566 psql -h localhost -U yaohu -d mahjong_scoreboard_system_test -c "SELECT current_database(), current_user;"
```

### 方案三：使用 postgres 用户（临时方案）

如果不想创建 `yaohu` 用户，可以临时使用 `postgres` 超级用户：

**修改应用配置**（在服务器上）：

```bash
# 编辑测试环境目录下的 .env 文件（如果存在）
cd /opt/yaohufox/testing
vi .env
```

添加或修改：

```bash
SPRING_DATASOURCE_USERNAME=postgres
SPRING_DATASOURCE_PASSWORD=你的postgres密码
```

**或在 Jenkinsfile 环境变量中设置**（不推荐，因为密码会暴露在代码中）。

## 完整修复脚本（一键执行）

在服务器上执行以下脚本，会自动检查并修复：

```bash
#!/bin/bash

DB_NAME="mahjong_scoreboard_system_test"
DB_USER="yaohu"
DB_PASSWORD="cch815566"

echo "=== 检查数据库用户 ==="

# 检查用户是否存在
USER_EXISTS=$(sudo -u postgres psql -tAc "SELECT 1 FROM pg_roles WHERE rolname='$DB_USER'")

if [ -z "$USER_EXISTS" ]; then
    echo "用户 $DB_USER 不存在，正在创建..."
    sudo -u postgres psql -c "CREATE USER $DB_USER WITH PASSWORD '$DB_PASSWORD';"
    echo "✅ 用户创建成功"
else
    echo "用户 $DB_USER 已存在"
fi

# 检查数据库是否存在
DB_EXISTS=$(sudo -u postgres psql -tAc "SELECT 1 FROM pg_database WHERE datname='$DB_NAME'")

if [ -z "$DB_EXISTS" ]; then
    echo "数据库 $DB_NAME 不存在，正在创建..."
    sudo -u postgres psql -c "CREATE DATABASE $DB_NAME ENCODING 'UTF8';"
    echo "✅ 数据库创建成功"
else
    echo "数据库 $DB_NAME 已存在"
fi

# 授予数据库权限
echo "授予数据库权限..."
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE $DB_NAME TO $DB_USER;"

# 授予 schema 权限
echo "授予 schema 权限..."
sudo -u postgres psql -d $DB_NAME -c "GRANT ALL ON SCHEMA public TO $DB_USER;"

# 授予现有表权限
echo "授予表权限..."
sudo -u postgres psql -d $DB_NAME -c "GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO $DB_USER;" 2>/dev/null || true
sudo -u postgres psql -d $DB_NAME -c "GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO $DB_USER;" 2>/dev/null || true

# 设置默认权限
echo "设置默认权限..."
sudo -u postgres psql -d $DB_NAME -c "ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO $DB_USER;"
sudo -u postgres psql -d $DB_NAME -c "ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO $DB_USER;"

# 验证连接
echo "验证用户连接..."
PGPASSWORD=$DB_PASSWORD psql -h localhost -U $DB_USER -d $DB_NAME -c "SELECT current_database(), current_user;" && echo "✅ 连接测试成功" || echo "❌ 连接测试失败"

echo "=== 修复完成 ==="
```

保存为 `fix_db_user.sh`，然后执行：

```bash
chmod +x fix_db_user.sh
sudo ./fix_db_user.sh
```

## 常见问题

### Q1: 用户存在但密码不匹配

**解决**：重置密码（见方案二），或检查应用配置中的密码是否正确。

### Q2: 用户有权限但连接被拒绝

**检查**：
```bash
# 检查 PostgreSQL 配置
sudo cat /etc/postgresql/*/main/pg_hba.conf | grep -v "^#"

# 应该看到类似：
# local   all             all                                     peer
# host    all             all             127.0.0.1/32            md5
```

如果 `host` 行不存在或不是 `md5`，需要修改 `pg_hba.conf` 并重启 PostgreSQL。

### Q3: 应用配置的密码与数据库不一致

**检查应用配置**：
- Jenkinsfile 中默认密码：`cch815566`
- 环境变量 `SPRING_DATASOURCE_PASSWORD`
- `.env` 文件中的密码

确保三者一致。

---

## 总结

1. **用户不存在** → 创建用户（方案一）
2. **密码错误** → 重置密码（方案二）
3. **权限不足** → 授予权限（方案一中的权限授予步骤）
4. **配置不一致** → 检查并统一密码配置

修复完成后，重新启动应用即可。

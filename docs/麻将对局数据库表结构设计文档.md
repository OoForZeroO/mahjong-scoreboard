# 麻将对局数据库表结构设计文档

## 1. 设计概述

### 1.1 业务需求分析
- 需要记录完整的麻将对局信息，包括对局时间、状态、参与玩家等
- 每个对局包含多轮计分，每轮记录各玩家的得分情况
- 支持对局状态管理（进行中、已完成）
- 记录完成对局时的倍率信息
- 需要统计每位玩家的总得分

### 1.2 表结构设计原则
- **分表设计**：总对局和轮次计分分离，便于查询和维护
- **数据完整性**：通过外键约束保证数据一致性
- **扩展性**：预留字段支持未来功能扩展
- **性能优化**：合理设计索引提升查询效率

## 2. 数据库表设计

### 2.1 对局总表 (matches)

**表名**: `matches`

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| match_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 对局唯一标识 |
| room_name | VARCHAR(100) | NULL | 对局房间名称（可选） |
| start_time | BIGINT | NOT NULL | 对局开始时间（时间戳） |
| end_time | BIGINT | NULL | 对局结束时间（时间戳） |
| status | VARCHAR(20) | NOT NULL, DEFAULT '进行中' | 对局状态：进行中、已完成 |
| total_rounds | INT | NOT NULL, DEFAULT 0 | 总轮数 |
| settlement_multiplier | DECIMAL(5,2) | NULL | 结算倍率 |
| create_time | BIGINT | NOT NULL | 创建时间 |
| update_time | BIGINT | NOT NULL | 更新时间 |

**索引设计**:
- PRIMARY KEY: `match_id`
- INDEX: `idx_status` (`status`)
- INDEX: `idx_start_time` (`start_time`)
- INDEX: `idx_create_time` (`create_time`)

### 2.2 对局参与者表 (match_participants)

**表名**: `match_participants`

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| participant_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 参与者唯一标识 |
| match_id | BIGINT | NOT NULL, FOREIGN KEY | 对局ID，关联matches表 |
| user_id | BIGINT | NULL, FOREIGN KEY | 用户ID，关联wechat_users表（可为空，支持游客） |
| user_name | VARCHAR(100) | NOT NULL | 用户名称 |
| total_score | INT | NOT NULL, DEFAULT 0 | 总得分 |
| create_time | BIGINT | NOT NULL | 创建时间 |
| update_time | BIGINT | NOT NULL | 更新时间 |

**索引设计**:
- PRIMARY KEY: `participant_id`
- INDEX: `idx_match_id` (`match_id`)
- INDEX: `idx_user_id` (`user_id`)

### 2.3 轮次计分表 (round_scores)

**表名**: `round_scores`

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| score_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 计分记录唯一标识 |
| match_id | BIGINT | NOT NULL, FOREIGN KEY | 对局ID，关联matches表 |
| participant_id | BIGINT | NOT NULL, FOREIGN KEY | 参与者ID，关联match_participants表 |
| round_number | INT | NOT NULL | 轮次编号（从1开始） |
| round_time | BIGINT | NOT NULL | 轮次时间（时间戳） |
| score | INT | NOT NULL | 本轮得分 |
| cumulative_score | INT | NOT NULL | 累计得分 |
| create_time | BIGINT | NOT NULL | 创建时间 |
| update_time | BIGINT | NOT NULL | 更新时间 |

**索引设计**:
- PRIMARY KEY: `score_id`
- UNIQUE KEY: `uk_match_participant_round` (`match_id`, `participant_id`, `round_number`)
- INDEX: `idx_match_id` (`match_id`)
- INDEX: `idx_participant_id` (`participant_id`)
- INDEX: `idx_round_number` (`round_number`)

### 2.4 对局结果表 (match_results)

**表名**: `match_results`

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| result_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 结果记录唯一标识 |
| match_id | BIGINT | NOT NULL, UNIQUE, FOREIGN KEY | 对局ID，关联matches表 |
| winner_id | BIGINT | NULL, FOREIGN KEY | 获胜者ID，关联match_participants表 |
| highest_score | INT | NULL | 最高分 |
| lowest_score | INT | NULL | 最低分 |
| total_duration | BIGINT | NULL | 对局总时长（毫秒） |
| create_time | BIGINT | NOT NULL | 创建时间 |

**索引设计**:
- PRIMARY KEY: `result_id`
- UNIQUE KEY: `uk_match_id` (`match_id`)
- INDEX: `idx_winner_id` (`winner_id`)

## 3. 表关系图

```
matches (对局总表)
├── match_participants (对局参与者表)
│   └── round_scores (轮次计分表)
└── match_results (对局结果表)
```

## 4. 建表SQL语句

### 4.1 创建对局总表
```sql
CREATE TABLE matches (
    match_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_name VARCHAR(100) NULL,
    start_time BIGINT NOT NULL,
    end_time BIGINT NULL,
    status VARCHAR(20) NOT NULL DEFAULT '进行中',
    total_rounds INT NOT NULL DEFAULT 0,
    settlement_multiplier DECIMAL(5,2) NULL,
    create_time BIGINT NOT NULL,
    update_time BIGINT NOT NULL,
    
    INDEX idx_status (status),
    INDEX idx_start_time (start_time),
    INDEX idx_create_time (create_time)
);
```

### 4.2 创建对局参与者表
```sql
CREATE TABLE match_participants (
    participant_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    match_id BIGINT NOT NULL,
    user_id BIGINT NULL,
    user_name VARCHAR(100) NOT NULL,
    total_score INT NOT NULL DEFAULT 0,
    create_time BIGINT NOT NULL,
    update_time BIGINT NOT NULL,
    
    INDEX idx_match_id (match_id),
    INDEX idx_user_id (user_id),
    
    FOREIGN KEY (match_id) REFERENCES matches(match_id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES wechat_users(id) ON DELETE SET NULL
);
```

### 4.3 创建轮次计分表
```sql
CREATE TABLE round_scores (
    score_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    match_id BIGINT NOT NULL,
    participant_id BIGINT NOT NULL,
    round_number INT NOT NULL,
    round_time BIGINT NOT NULL,
    score INT NOT NULL,
    cumulative_score INT NOT NULL,
    create_time BIGINT NOT NULL,
    update_time BIGINT NOT NULL,
    
    UNIQUE KEY uk_match_participant_round (match_id, participant_id, round_number),
    INDEX idx_match_id (match_id),
    INDEX idx_participant_id (participant_id),
    INDEX idx_round_number (round_number),
    
    FOREIGN KEY (match_id) REFERENCES matches(match_id) ON DELETE CASCADE,
    FOREIGN KEY (participant_id) REFERENCES match_participants(participant_id) ON DELETE CASCADE
);
```

### 4.4 创建对局结果表
```sql
CREATE TABLE match_results (
    result_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    match_id BIGINT NOT NULL UNIQUE,
    winner_id BIGINT NULL,
    highest_score INT NULL,
    lowest_score INT NULL,
    total_duration BIGINT NULL,
    create_time BIGINT NOT NULL,
    
    INDEX idx_winner_id (winner_id),
    
    FOREIGN KEY (match_id) REFERENCES matches(match_id) ON DELETE CASCADE,
    FOREIGN KEY (winner_id) REFERENCES match_participants(participant_id) ON DELETE SET NULL
);
```

## 6. 常用查询示例

### 6.1 查询对局详情
```sql
SELECT 
    m.match_id,
    m.room_name,
    m.start_time,
    m.end_time,
    m.status,
    m.total_rounds,
    m.settlement_multiplier,
    COUNT(mp.participant_id) as participant_count
FROM matches m
LEFT JOIN match_participants mp ON m.match_id = mp.match_id
WHERE m.match_id = 1
GROUP BY m.match_id;
```

### 6.2 查询对局参与者得分情况
```sql
SELECT 
    mp.user_name,
    mp.seat_position,
    mp.total_score,
    mp.is_winner,
    rs.round_number,
    rs.score,
    rs.cumulative_score
FROM match_participants mp
LEFT JOIN round_scores rs ON mp.participant_id = rs.participant_id
WHERE mp.match_id = 1
ORDER BY mp.seat_position, rs.round_number;
```

### 6.3 查询对局统计信息
```sql
SELECT 
    m.match_id,
    m.room_name,
    m.status,
    m.total_rounds,
    m.settlement_multiplier,
    mr.highest_score,
    mr.lowest_score,
    mr.total_duration,
    w.user_name as winner_name
FROM matches m
LEFT JOIN match_results mr ON m.match_id = mr.match_id
LEFT JOIN match_participants w ON mr.winner_id = w.participant_id
WHERE m.match_id = 1;
```

## 7. 设计优势

### 7.1 分表设计优势
- **性能优化**：轮次计分表独立，避免单表数据过大
- **查询效率**：可根据业务需求灵活查询不同层级数据
- **维护便利**：表结构清晰，便于维护和扩展

### 7.2 数据完整性
- **外键约束**：保证数据关联的完整性
- **唯一约束**：防止重复数据
- **级联删除**：保证数据一致性

### 7.3 扩展性
- **预留字段**：支持未来功能扩展
- **索引优化**：支持高效查询
- **冗余设计**：关键字段冗余，提升查询性能

## 8. 注意事项

1. **时间戳存储**：使用BIGINT存储时间戳，便于跨平台兼容
2. **分数计算**：累计得分需要实时更新，建议在应用层处理
3. **并发控制**：多用户同时计分时需要注意并发控制
4. **数据备份**：重要数据需要定期备份
5. **性能监控**：大数据量时需要监控查询性能

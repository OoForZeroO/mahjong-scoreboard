# 502 错误诊断和修复指南

## 问题描述

前端或 Postman 调用测试环境接口（如 `https://test.yaohufox.com/api/...`）时返回 **502 Bad Gateway**，且页面显示 `nginx/1.18.0 (Ubuntu)`。说明 Nginx 反向代理无法从上游（本机 8082 端口的 Spring Boot 应用）获取有效响应。

---

## 快速排查（按顺序在服务器执行）

SSH 登录测试环境服务器后，按顺序执行下面命令，根据结果判断问题点：

| 步骤 | 命令 | 说明 |
|------|------|------|
| 1 | `ps aux \| grep java` | 看是否有 mahjong/scoreboard 相关 Java 进程，没有则后端未启动 |
| 2 | `ss -tlnp \| grep 8082` 或 `netstat -tlnp \| grep 8082` | 看 8082 是否在监听，没有则应用未监听或端口不对 |
| 3 | `curl -s -o /dev/null -w "%{http_code}" http://localhost:8082/actuator/health` | 返回 200 说明后端正常，非 200 说明应用异常 |
| 4 | `curl -s http://localhost:8082/api/test/hello` | 直接测接口，有正常 JSON 则后端 OK，问题在 Nginx |
| 5 | `sudo tail -20 /var/log/nginx/error.log` 或 `sudo tail -20 /opt/yaohufox/logs/nginx/testing-error.log` | 看是否有 `connection refused`、`upstream timed out` 等 |

**常见结论**：
- 步骤 1/2 失败 → **后端未启动或未用 testing 配置**：到 `/opt/yaohufox/testing` 用 `--spring.profiles.active=testing` 启动，或重新通过 Jenkins 部署测试环境。
- 步骤 3/4 成功、步骤 5 有错误 → **Nginx 连不上或超时**：确认 Nginx 里 `proxy_pass` 为 `http://127.0.0.1:8082` 或 `http://localhost:8082`，然后 `sudo nginx -t && sudo nginx -s reload`。
- 步骤 3/4 失败 → 看应用日志（如 `/opt/yaohufox/testing/app.log`）排查启动失败或数据库连接等问题。

## 502 错误原因分析

502 错误表示 Nginx（网关）无法从后端服务（Spring Boot 应用）获取有效响应。常见原因：

1. **后端服务未启动**
2. **端口配置不匹配**（Nginx 配置的端口与后端服务实际端口不一致）
3. **后端服务崩溃或响应超时**
4. **Nginx 配置错误**

## 诊断步骤

### 步骤1：检查后端服务是否运行

在服务器上执行：

```bash
# 检查 Java 进程是否运行
ps aux | grep java | grep mahjong

# 检查端口是否被监听（测试环境通常是 8082）
netstat -tlnp | grep 8082
# 或
ss -tlnp | grep 8082

# 检查应用日志
tail -f /path/to/application.log
# 或查看 Spring Boot 日志
journalctl -u your-service-name -f
```

**预期结果**：
- 应该看到 Java 进程在运行
- 应该看到端口 8082（或配置的端口）被监听
- 如果没有，说明服务未启动

### 步骤2：检查 Nginx 配置的端口

在服务器上执行：

```bash
# 查看 Nginx 配置中 proxy_pass 指向的端口
sudo nginx -T | grep -A 10 "server_name test.yaohufox.com" | grep proxy_pass
```

**预期结果**：
- 应该看到 `proxy_pass http://localhost:8082;`（测试环境）
- 如果端口不匹配，需要修改配置

### 步骤3：测试后端服务是否响应

在服务器上执行：

```bash
# 直接测试后端服务（绕过 Nginx）
curl http://localhost:8082/api/v1/matches

# 如果端口是 8080，测试：
curl http://localhost:8080/api/v1/matches

# 测试健康检查接口
curl http://localhost:8082/actuator/health
# 或
curl http://localhost:8080/actuator/health
```

**预期结果**：
- 如果返回数据：说明后端服务正常，问题在 Nginx 配置
- 如果连接失败：说明后端服务未启动或端口错误

### 步骤4：检查 Nginx 错误日志

在服务器上执行：

```bash
# 查看 Nginx 错误日志
sudo tail -f /opt/yaohufox/logs/nginx/testing-error.log
# 或
sudo tail -f /var/log/nginx/error.log

# 在前端发起请求，观察日志输出
```

**常见错误信息**：
- `connect() failed (111: Connection refused)` - 后端服务未启动或端口错误
- `upstream timed out` - 后端服务响应超时
- `no live upstreams` - 后端服务不可用

## 问题确认

根据配置文件分析：
- **Nginx 配置**：`proxy_pass http://localhost:8082;`（测试环境）
- **应用配置**：
  - `application.properties`: `server.port=8080`（默认配置）
  - `application-testing.yml`: `server.port=8082`（测试环境配置）
  - `application-production.yml`: `server.port=8081`（生产环境配置）

**问题原因**：应用可能没有使用测试环境配置文件启动，导致端口不匹配。

## 修复方案

### 方案1：使用正确的配置文件启动服务（推荐）

确保使用测试环境配置文件启动：

```bash
# 方式1：使用 Spring Profile
java -jar mahjong-scoreboard-start/target/mahjong-scoreboard-start-*.jar --spring.profiles.active=testing

# 方式2：使用环境变量
export SPRING_PROFILES_ACTIVE=testing
java -jar mahjong-scoreboard-start/target/mahjong-scoreboard-start-*.jar

# 方式3：如果使用 systemd，修改服务配置
# 在 [Service] 部分添加：
# Environment="SPRING_PROFILES_ACTIVE=testing"
```

**验证**：启动后检查端口
```bash
netstat -tlnp | grep 8082
# 应该看到应用监听在 8082 端口
```

### 方案2：启动后端服务（如果服务未启动）

```bash
# 进入项目目录
cd /path/to/mahjong-scoreboard

# 启动服务（根据实际启动方式）
# 方式1：使用 Maven
mvn spring-boot:run

# 方式2：使用 JAR 文件
java -jar mahjong-scoreboard-start/target/mahjong-scoreboard-start-*.jar

# 方式3：使用 systemd 服务（如果配置了）
sudo systemctl start mahjong-scoreboard
sudo systemctl status mahjong-scoreboard
```

### 方案2：修复端口配置不匹配

#### 情况1：应用配置的端口与 Nginx 配置不一致

**检查应用配置** (`application.properties`):
```properties
server.port=8080  # 应用实际运行端口
```

**检查 Nginx 配置** (`/opt/yaohufox/config/nginx/sites-available/mahjong-testing.conf`):
```nginx
proxy_pass http://localhost:8082;  # Nginx 配置的端口
```

**修复方法**：

**选项A：修改应用端口为 8082**（推荐，因为 Nginx 已配置）

编辑 `application.properties`:
```properties
server.port=8082
```

**选项B：修改 Nginx 配置为 8080**

编辑 Nginx 配置文件：
```nginx
proxy_pass http://localhost:8080;
```

然后重新加载 Nginx：
```bash
sudo nginx -t
sudo nginx -s reload
```

### 方案3：检查并修复 Nginx 配置

确保 Nginx 配置正确：

```nginx
server {
    listen 443 ssl http2;
    server_name test.yaohufox.com;
    
    # ... SSL 配置 ...
    
    location /api/ {
        proxy_pass http://localhost:8082;  # 确保端口正确
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

### 方案4：检查数据库连接（可能导致服务启动失败）

如果服务启动失败，检查数据库连接：

```bash
# 检查数据库是否运行
sudo systemctl status postgresql
# 或
ps aux | grep postgres

# 测试数据库连接
psql -h localhost -U postgres -d mahjong_scoreboard_system
```

## 快速诊断命令

在服务器上执行以下命令进行快速诊断：

```bash
#!/bin/bash
echo "=== 502 错误诊断 ==="

echo "1. 检查后端服务进程..."
ps aux | grep java | grep mahjong || echo "❌ 后端服务未运行"

echo "2. 检查端口监听..."
netstat -tlnp | grep -E "8080|8082" || echo "❌ 端口未监听"

echo "3. 测试后端服务..."
curl -s http://localhost:8082/api/v1/matches > /dev/null && echo "✅ 后端服务正常" || echo "❌ 后端服务无响应"

echo "4. 检查 Nginx 配置..."
sudo nginx -T | grep -A 5 "proxy_pass" | grep -E "8080|8082" || echo "❌ 未找到 proxy_pass 配置"

echo "5. 检查 Nginx 错误日志（最近10行）..."
sudo tail -10 /opt/yaohufox/logs/nginx/testing-error.log 2>/dev/null || echo "❌ 无法读取日志"
```

## 常见问题解决

### 问题1：服务启动后立即退出

**可能原因**：
- 数据库连接失败
- 端口被占用
- 配置文件错误

**解决方法**：
```bash
# 查看详细启动日志
java -jar your-app.jar --debug

# 检查端口占用
lsof -i :8082
# 或
netstat -tlnp | grep 8082
```

### 问题2：服务运行但 Nginx 仍返回 502

**可能原因**：
- Nginx 配置的端口错误
- 防火墙阻止连接
- 服务监听在 127.0.0.1 而不是 0.0.0.0

**解决方法**：
```bash
# 检查服务监听的地址
netstat -tlnp | grep java

# 应该看到类似：0.0.0.0:8082 而不是 127.0.0.1:8082
# 如果只监听 127.0.0.1，修改配置：
# server.address=0.0.0.0
```

### 问题3：服务响应超时

**解决方法**：
增加 Nginx 超时时间：
```nginx
proxy_connect_timeout 120s;
proxy_send_timeout 120s;
proxy_read_timeout 120s;
```

## 验证修复

修复后，执行以下步骤验证：

1. **检查服务状态**：
```bash
ps aux | grep java | grep mahjong
netstat -tlnp | grep 8082
```

2. **测试后端服务**：
```bash
curl http://localhost:8082/api/v1/matches
```

3. **测试通过 Nginx**：
```bash
curl https://test.yaohufox.com/api/v1/matches
```

4. **检查 Nginx 日志**：
```bash
sudo tail -f /opt/yaohufox/logs/nginx/testing-error.log
```

## 总结

502 错误通常是后端服务未启动或端口配置不匹配导致的。按照以下顺序排查：

1. ✅ 检查后端服务是否运行
2. ✅ 检查端口配置是否匹配
3. ✅ 测试后端服务是否响应
4. ✅ 检查 Nginx 错误日志
5. ✅ 修复配置并重启服务

按照上述步骤诊断和修复，通常可以解决 502 错误。

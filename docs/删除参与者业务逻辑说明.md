# 删除参与者业务逻辑说明

## 1. 接口信息

### API 端点
- **接口路径**: `DELETE /api/v1/matches/participants/batch`
- **请求方法**: `DELETE`
- **请求体**: `List<Long>` - 参与者ID列表
  ```json
  [1, 2, 3]
  ```

### 接口位置
- **Controller**: `MatchController.deleteParticipants()`
- **Service**: `MatchServiceImpl.deleteParticipants()`

## 2. 业务逻辑流程

### 2.1 前置验证
1. **参数校验**
   - 检查 `participantIds` 是否为空或null
   - 如果为空，返回400错误："参与者ID列表不能为空"

### 2.2 批量删除处理
对每个参与者ID执行以下步骤：

#### 步骤1: 查找参与者
```java
Optional<MatchParticipant> participantOpt = pdao.findById(participantId);
```
- 如果参与者不存在，**跳过**该ID，继续处理下一个（不抛出异常）
- 记录警告日志："参与者不存在，跳过删除"

#### 步骤2: 获取对局信息
```java
Long matchId = participant.getMatch() != null ? participant.getMatch().getMatchId() : null;
```
- 记录日志，包含参与者ID和对局ID

#### 步骤3: 检查轮次记录（核心业务规则）
```java
List<RoundScore> roundScores = rdao.findByParticipantOrderByRoundNumberAsc(participant);
```

**关键业务规则**：
- **如果参与者在 `round_scores` 表中有任何记录，则不允许删除**
- 查询该参与者的所有轮次得分记录
- 如果 `roundScores` 不为空，抛出异常：`IllegalStateException("玩家已有对战记录不可删除！")`

#### 步骤4: 执行删除
- 只有在通过轮次记录检查后，才执行删除操作
- 使用 `pdao.deleteById(participantId)` 删除参与者

## 3. 业务规则说明

### 3.1 核心限制规则
**规则**: 如果参与者在轮次表（`round_scores`）中有记录，则不允许删除

**原因**:
- 保护数据完整性：删除有轮次记录的参与者会破坏对局历史数据的完整性
- 防止数据丢失：轮次记录依赖参与者ID，删除参与者可能导致关联数据丢失或孤立

### 3.2 删除条件
**可以删除的情况**:
- 参与者在 `round_scores` 表中**没有**任何记录
- 参与者可能还没有参与任何轮次的计分

**不能删除的情况**:
- 参与者在 `round_scores` 表中有**至少一条**记录
- 即使只有一条轮次得分记录，也不允许删除

## 4. 事务管理

### 4.1 事务特性
```java
@Transactional
public void deleteParticipants(List<Long> participantIds)
```

- **事务范围**: 整个批量删除操作在同一个事务中
- **回滚策略**: 如果任何一个参与者有轮次记录，整个批量操作都会回滚
- **原子性**: 要么全部成功，要么全部回滚

### 4.2 异常处理
- **IllegalStateException**: 当参与者有轮次记录时抛出，Controller层捕获并返回400错误
- **其他异常**: 返回500错误，记录详细日志

## 5. 响应格式

### 5.1 成功响应
```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

### 5.2 不允许删除响应（有轮次记录）
**注意**: 当参与者有轮次记录时，HTTP状态码为 **200**，而不是400
```json
{
  "code": 200,
  "message": "玩家已有对战记录不可删除！",
  "data": null
}
```

### 5.3 失败响应（其他错误）
```json
{
  "code": 500,
  "message": "批量删除参与者失败: [错误详情]",
  "data": null
}
```

## 8. 数据表关系

```
match_participants (参与者表)
    ↓ (participant_id)
round_scores (轮次得分表)
```

**外键关系**:
- `round_scores.participant_id` → `match_participants.id`
- 如果删除参与者，会导致 `round_scores` 表中的关联记录变成孤立数据

## 9. 使用示例

### 9.1 成功删除（无轮次记录）
```bash
DELETE /api/v1/matches/participants/batch
Content-Type: application/json

[100, 101]
```

**结果**: 如果参与者100和101都没有轮次记录，删除成功

### 9.2 失败删除（有轮次记录）
```bash
DELETE /api/v1/matches/participants/batch
Content-Type: application/json

[50, 51]
```

**结果**: 如果参与者50有轮次记录，抛出异常，整个批量操作回滚

## 10. 注意事项

1. **批量操作的原子性**: 如果列表中有任何参与者有轮次记录，整个批量删除都会失败并回滚
2. **不存在的参与者**: 如果列表中包含不存在的参与者ID，会跳过该ID，不影响其他参与者的删除
3. **数据完整性**: 删除前必须确保没有轮次记录，这是硬性业务规则
4. **日志追踪**: 所有关键操作都有详细日志，便于问题排查
